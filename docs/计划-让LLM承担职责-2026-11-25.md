# 计划：让 LLM 真正承担职责（2026-11-25）

> 状态：**计划，未实施**
> 目标：把 LLM 从"可选的选择题答题器"变成"决定下一步干什么的调度者"，并给出可量化的证据。

## 一、现状审计（先摆事实）

### 1.1 LLM 现在只在四个地方出现

| 位置 | 做什么 | 触发条件 | 证据 |
|---|---|---|---|
| `fwmap/discover.py` `ask()` | 在 5 种路由发现机制里选一个 | 跑 `routes` 且未加 `--no-llm` | `discover.py` 三处 `chat(` |
| `fwmap/unpack.py` `ask()` | 给解包工具排序 | 跑 `unpack`/`extract` 且未加 `--no-llm` | `unpack.py` 三处 |
| `fwmap/toolbus.py` `choose()` | 给同类工具排序 | 同上 | `toolbus.py` 一处 |
| `fwmap/agent/judge.py` | 读反编译片段，答"有无边界检查/是否被重赋值" | **只有 `triage --agent`** | `triage.py:740` `if use_agent:` |

### 1.2 三个具体问题

1. **主流程默认不叫模型**：`cli.py:204` 的 `triage --agent` 是**可选开关**，不加就跑纯规则。
   最近几天的实验大多带 `--no-llm`（模型服务没起），所以日志里几乎没有模型痕迹。
2. **模型只做"选择题"**：选机制、排工具、答三个是非题。
   **没有任何一处是"模型看到当前状态，决定下一步做什么"**。
3. **`planner_llm.py` 是半成品**：`fwmap/agent/planner_llm.py` 里已经写好了
   `choose(state, catalog, ...)`（"让模型选下一步调哪个工具"），但**没有任何地方 import 它**。

### 1.3 为什么这是个问题

论文题目是"端到端自动漏洞挖掘"，创新点之一是"大模型受限取证"。
但当前状态下 `--no-llm` 一键关掉、结果几乎不变 —— **创新点站不住**，
答辩时"不用模型会怎样"这个问题无法回答。

## 二、目标与验收

### 2.1 目标

| 编号 | 目标 | 落点 |
|---|---|---|
| G1 | 模型成为**调度者**：观察状态 → 选下一步动作 → 执行 → 看结果 | 新增 `fwmap/agent/loop.py` |
| G2 | 主流程**默认用模型**（可关） | `triage` / `cli.py` |
| G3 | 模型能**补全参数**（读网页/JS，推断隐藏字段） | 新增 `fwmap/agent/param_llm.py` |
| G4 | 模型能**看错误页调整请求** | 新增 `fwmap/agent/retry_llm.py` |
| G5 | 模型能**解释崩溃**（指到具体语句） | 新增 `fwmap/agent/explain.py` |

### 2.2 验收（必须可量化）

| 指标 | 现在 | 目标 |
|---|---|---|
| 端到端走通的固件数 | 2/6（DIR-615、DIR-816L） | ≥3/6 |
| `--no-llm` 与默认的结论差异 | ≈0 | **≥1 台固件必须依赖模型才能走通** |
| 参数补齐成功率 | 不适用（无此能力） | 在"参数没抽全"的样本上 ≥50% |
| 平均人工介入次数 | 当前需人工选路径 | 0（全自动跑完） |

## 三、改造项（按优先级）

### P0-1 接上调度循环（核心，约 1 天）

**新文件**：`fwmap/agent/loop.py`

```python
# 状态：模型能看到的全部信息
state = {
    "rootfs": str, "binary": str, "arch": str,
    "steps_done": [{"tool": str, "ok": bool, "detail": str}],
    "routes": int, "handlers": int,
    "findings": [{"verdict": str, "what": str}],
    "budget": {"steps_left": int, "seconds_left": int},
}

def step(state, catalog, chat) -> dict | None:
    """返回 {"tool": name, "kwargs": {...}, "why": "..."}；None 表示收工。"""

def run(rootfs, binary, *, chat=None, max_steps=12, log=print) -> dict:
    """观察→决策→执行→记录，循环直到：拿到成果 / 没预算 / 模型说 done。"""
```

**接口契约（安全边界）**

| 约束 | 做法 |
|---|---|
| 只能调用白名单工具 | `catalog` 来自 `toolbus.all_tools()`，名字不在表里直接丢弃 |
| 参数必须过 schema | 每个工具声明 `kwargs_schema`；校验失败即拒绝并记一条观察 |
| 不能无限跑 | `max_steps=12`、`seconds_left`、已有 `RLIMIT_NPROC/CPU` |
| 每步必须有验收 | 复用 `toolbus.run()` 的 `success` 判据，失败原因进入下一步的观察 |
| 全程可回放 | `trace.json` 记录每步的 state/决策/结果 |

**复用**：`fwmap/agent/planner_llm.py` 的 `choose()` 已有雏形，改造成 `step()` 即可
（增加 kwargs 校验与失败反馈）。

### P0-2 主流程默认开模型（约 0.5 小时）

**改动点**

| 文件 | 改什么 |
|---|---|
| `fwmap/cli.py:204` | `triage` 去掉 `--agent` 开关，改成 `--no-llm` 反向开关 |
| `fwmap/triage.py:740` | `if use_agent:` → 默认 True；模型不可用时**显式降级并记日志**，不静默 |
| `fwmap/agent/llm.py` | `find_model()` 增加环境变量/端口自动发现，失败返回明确原因 |

### P1 参数补全（约半天到 1 天）

**新文件**：`fwmap/agent/param_llm.py`

```python
def infer(page_html: str, js_text: str, known: list[str], chat) -> list[str]:
    """从页面与 JS 里推断该表单实际提交哪些参数，按可能性排序。"""
```

**硬约束（防幻觉）**：模型给出的每个参数名**必须能在页面文本里 grep 到**，
否则丢弃并记一条"模型编了参数名"。这条用 `pages.py` 的原文即可验证。

**接入点**：`fwmap/poc.py:guess_param()` —— 现在只从 M3 链推断，
补全失败时调用 `infer()`。

**为什么值得做**：今天打 `formStaDrvSetup` 没成功，很可能就是缺 `stadrv_type` /
`stadrv_ssid` / `submit-url` 这些页面字段。

### P1-2 看错误页调请求（约 1 天）

**新文件**：`fwmap/agent/retry_llm.py`

```python
def adjust(request, response, server_strings, chat) -> dict | None:
    """根据错误响应补/改字段；返回新的 request，或 None 表示放弃。"""
```

**约束**：最多重试 3 次；每次必须产生**可观测差异**（响应长度/状态变化），
否则停止 —— 避免模型原地打转烧预算。

### P2 崩溃解释（约半天）

**新文件**：`fwmap/agent/explain.py`

```python
def explain(crash: dict, function_text: str, chat) -> dict:
    """返回 {"what": "...", "stmt": int}；stmt 必须是片段里的真实行号。"""
```

**验收**：`stmt` 在片段范围内，且能被 `judge.py` 的同一套"下标引用"校验。

## 四、消融实验（论文证据）

**样本**：现有 6 台（DIR-615、DIR-816L、Edimax×2、ASUS、TEW-818）

**配置**

| 组 | 命令 |
|---|---|
| A | `triage --no-llm` |
| B | `triage`（默认，模型开启） |

**记录**

1. 端到端是否走通（能出验证结论）
2. 路由 handler 命中数
3. 动态验证结论分布（exec / crash / no-crash / no-listener）
4. 步骤数、耗时
5. **模型独有的贡献**：只在 B 组出现的结论（逐条列出）

**预期**：至少 1 台固件在 A 组走不通、B 组走通（很可能是参数补全那一步）。

## 五、风险与回滚

| 风险 | 处理 |
|---|---|
| 模型乱调工具、烧预算 | 白名单 + schema 校验 + `max_steps` + 时间预算 |
| 模型编参数名 | 必须在页面文本里 grep 得到，否则丢弃 |
| 模型拖慢流程 | 默认开启但**可 `--no-llm` 一键关闭**；单步超时可配 |
| 破坏现有结论 | 所有工具仍走各自的 `success` 判据；合不拢就不记 |
| 回滚 | git tag `plan-2026-11-25-llm` 之前的状态可直接 reset |
