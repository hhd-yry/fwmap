## 九、已知限制（写进论文"讨论"）

1. 动态验证的自动判定在 fork 型服务上有时序误差；
2. 只完成 2 台固件的端到端闭环（Edimax 命令执行、DIR-615 DoS 候选）；
3. 三台固件卡在 NVRAM（需全系统模拟）；
4. 1.5B 模型的参数识别能力弱于确定性解析——模型适合"决策"，不适合"认字段"。

## 八点五、消融实验（2026-11-26 实测）

**样本**：Edimax BR-6478AC V2 1.23 `bin/webs`（137 条链，保留 39）
**命令**：`fwmap triage … --binaries 1 --top-chains 4 --samples 1 --no-verify`（另一组加 `--no-llm`）

| 指标 | 有 LLM | 无 LLM |
|---|---|---|
| 候选链 / 保留 | 137 / 39 | 137 / 39 |
| 复核条数（agent_rows） | **4** | 0 |
| 判定分布 | REFUTED 2（high）· REVIEW 2（low） | 无（全部 UNPROVEN） |
| CONFIRMED | 0 | 0 |
| 耗时 | **922.6 s** | 736.2 s |
| 时间开销 | +186 s（+25%） | —— |

**逐条判定**（有 LLM 组）：

| 函数 | 类型 | 判定 | 置信 | 说明 |
|---|---|---|---|---|
| formStaDrvSetup | ci | **REFUTED** | high | 模型称"污染已断" |
| wiz_5in1_redirect | ci | REFUTED | high | 模型称"命令串前有白名单" |
| formUploadIE | fmt | REVIEW | low | 模型说有检查，但引用的是下界检查 |
| formUpload | fmt | REVIEW | low | 同上 |

**关键观察（论文可用的反例）**：

> `formStaDrvSetup` 被模型以 **high 置信判为 REFUTED**，而我们的动态验证在同一路由、
> 同一参数上**打出了命令执行**（`FWMAP-TOOL-CONFIRMED`）。
> 这说明：模型的判定只能当作"假设"，**证据必须能否决它**——这也正是本系统
> "证据仲裁"设计的由来。

**结论**：LLM 的价值不是"减少候选"，而是**给候选加上可复核的假设**
（哪些看起来已断、哪些需要重点看），代价是 +25% 运行时间；
其 high 置信判定仍可能错，因此必须保留"动态证据否决"的通道。
