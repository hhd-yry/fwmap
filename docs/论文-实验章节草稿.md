## 6.2 端到端可行性

**实验目的**：验证系统能否在无人指定分析对象的前提下，从镜像走到带证据的结论。

**结果**：

| 环节 | Edimax BR-6478AC V2 1.23 |
|---|---|
| 解包 | ✅ 自动切出 squashfs 并验收 |
| 静态候选 | 93 条链，保留 27 条 |
| 路由抽取 | 188 条（来自页面表单） |
| 路由验收 | ⚠️ `/goform/*` 在 Boa 上全部 404（页面与实现不符） |
| 认证 | ✅ 默认口令 `admin:1234` |
| 动态验证 | ✅ 命令执行确认（`FWMAP-TOOL-CONFIRMED`） |

**结论**：端到端在"Web 服务自包含、无需常驻守护进程"的固件上成立；
在页面与实现不一致的目标上，路由自证机制能识别出"候选是错的"，避免误判。

## 6.3 有效性：能否挖到并确认

**实验目的**：检验系统能否自动定位**已知漏洞**并给出可核查证据。

**结果**：

| 发现 | 路由/参数 | 证据 | 对应 CVE |
|---|---|---|---|
| E1 | `/goform/formStaDrvSetup` `rootAPmac` | 命令执行，`/tmp` 出现证据文件 | CVE-2026-10127 |
| E2 | `/goform/mp` `command` | SIGSEGV @512B，稳定复现 | CVE-2026-12810 |

**关键细节（本文增量）**：该处理器把参数拼进 `echo '%s' > /tmp/...`，
且在 `;` 处截断。因此经典的 `;id;` 与裸反引号**全部无效**，
只有**闭合单引号 + 命令替换**（`MAC'$(cmd)'`）才能执行。
这条结论来自对 M3 给出的守卫（guard）片段的解读，不是试错。

**对照实验**（同一请求，仅换载荷）：

| 载荷 | 执行 |
|---|---|
| `MAC;touch /tmp/x;` | ❌ |
| ``MAC`touch /tmp/x` `` | ❌ |
| `MAC'$(touch /tmp/x)'` | ✅ |

## 6.4 可信度：四态结论与假阳性抑制

**实验目的**：检验"结论是否可复核"，即能否区分"漏洞"与"环境问题"。

**结果**：

| 场景 | 现象 | 系统结论 |
|---|---|---|
| DIR-615 `GET /login.cgi` | 服务 SIGSEGV | **崩溃（未认证可触发）** |
| DIR-615 `GET /login.cgi?graph_id=1` | 1818 B 正常页 | 未崩溃 |
| Edimax `fwupdate.cgi`（早期样本） | 任何请求都崩 | **环境缺失，不报** |
| ASUS / TEW-818 | 服务起不来 | **服务未启动（未验证）** |

**意义**：传统工具会把第 1 行与第 3 行都记成"高危崩溃"；
本系统通过对照与输入相关性分析，把第 3 行排除，把第 4 行标为"未验证"而不是"安全"。

## 6.5 消融实验：有/无大模型

**实验目的**：回答"不用大模型会怎样"。

**设计**：同一二进制（Edimax BR-6478AC V2 1.23 `bin/webs`），其余参数完全一致，
只切换 `--no-llm`。

**结果**：

| 指标 | 有 LLM | 无 LLM |
|---|---|---|
| 候选链 / 保留 | 137 / 39 | 137 / 39 |
| 复核条数 | **4** | 0 |
| 判定分布 | REFUTED 2（high）· REVIEW 2（low） | 无（全部 UNPROVEN） |
| 耗时 | **922.6 s** | 736.2 s |
| 时间开销 | +186 s（**+25%**） | —— |

**观察**：LLM 不改变候选数量，它给候选加上"假设"——
4 条被标成"看起来已断（2 条）"或"引用的检查不构成保护（2 条）"，
人工可以优先处理这 4 条；代价是 25% 的运行时间。

**关键反例**（写进正文）：
`formStaDrvSetup` 被模型以 **high 置信判为 REFUTED**，而动态验证在同一路由、
同一参数上打出了命令执行。因此模型的判定只能作为假设，**必须允许证据否决**——
这正是本文"证据仲裁"机制的依据。

**原有定性证据**（可写进正文）：

| 现象 | 说明 |
|---|---|
| 模型判 `formStaDrvSetup` "污染已断" | 动态验证却打出命令执行 → **证据推翻推理** |
| 1.5B 模型读页面补参数 | 回复空数组；确定性解析反而抽出 `rootAPmac` |
| 模型在 agent 循环里选动作 | 3 步中 2 次由模型决策，1 次因重复被守卫拦下 |

**待补**：定量表格（走通率、结论数、耗时）。

## 6.7 讨论与限制

1. **fork 型服务的状态判定**：进程生命周期与请求不一一对应，
   自动判定存在时序误差（已提供"生成 + 执行"降级路径）；
2. **端到端覆盖**：仅 2 台固件走完闭环，3 台受限于 NVRAM（需全系统模拟）；
3. **模型能力**：1.5B 模型适合"决策"（选机制/选动作），不适合"认字段"；
4. **样本量**：6 台固件不足以做统计显著性检验，结论以案例形式呈现。

## 6.8 本章小结

系统在真实固件上完成了"候选收敛 → 路由自证 → 证据驱动验证"的闭环，
复现了两条公开漏洞并在一条上给出了公开报告未涉及的可用性分析（分号截断的绕过）；
同时明确划出了当前能力边界（fork 型服务、NVRAM 依赖、模型能力上限）。
