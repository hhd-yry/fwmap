## 三、过程中的一个教训（值得写进论文）

第一轮重跑（修引用规则之后、放宽之前）得到：

```
temp00  0/5      temp07  4/5      anon  0/5
```

看起来像"模型变差了"，实际是**我的校验写错了**：

模型给出的引用是两条 —— 对照组的 `/apply.cgi 1818B` 和目标的 `/login.cgi 0B`。
我当时要求**每条引用都必须提到目标对象**，于是把带对照组的正确结论整条拒掉。

改成「至少一条能对上目标，其余引用只需真实存在」之后，结果立刻回到 5/5。

**这个反例很有价值**：校验过严会伪造成"模型不行"，
和校验过松伪造成"模型很行"是同一类错误的两面。论文里可以放在"规则与模型的职责边界"一节。

## 四、重算口径（写死）

1. 每轮遍历**全部**结论，按 `uri` 精确匹配 + `kind` 精确匹配，每轮最多计一次；
2. 两个分母都给：`命中/有效`（成功读入）与 `命中/计划`（计划轮次）；
3. 损坏、缺失分别计数，不静默跳过，不拿"成功读入数"冒充计划轮次；
4. 原件只读；汇总结果另存；
5. 旧记录缺 `status` 字段时显示「（旧记录，无状态字段）」，不替它推断。
