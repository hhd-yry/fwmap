### ⚠️ 受阻：消融实验（任务 2）

在本机跑 `triage` 时 **Ghidra 卡在 M2**：日志停在 `[2/4] M2`，
java 进程 CPU 停在 85 秒不再增长，4 分钟无进展（两次复现）。
磁盘剩余 47 GB，不是空间问题。

已确认不是代码问题（同一二进制此前跑通过，产物 `webs_m2.json` 还在）。

**根因找到了**（手动跑 Ghidra headless 复现）：

```
INFO  Creating project: ... (DefaultProject)
ERROR Abort due to error: 拒绝访问。 (HeadlessAnalyzer)
  at org.apache.felix.framework.cache.BundleCache.<init>(BundleCache.java:161)
  at ghidra.app.plugin.core.osgi.BundleHost.startFramework(BundleHost.java:470)
```

Ghidra 12.2 启动时无法创建脚本 bundle 缓存（Felix BundleCache），Windows 报"拒绝访问"。
已排除：磁盘空间（47 GB 空闲）、安装目录只读（可写）、`%USERPROFILE%\.ghidra` 不存在
（已手动创建且可写）。

**继续排查的结果：**

| 尝试 | 结果 |
|---|---|
| 手动创建 `%USERPROFILE%\.ghidra`（可写） | 仍失败，且该目录始终为空 |
| `icacls /reset /T` 重置安装目录 ACL | 无效（DENY 是从 `C:\deepseek` **继承**来的，重置子目录去不掉） |
| 把 Ghidra 复制到 `C:\ghidra_12.2_PUBLIC`（继承干净 ACL） | **仍失败**，同样的 BundleCache 拒绝访问 |
| 用干净 `USERPROFILE` 启动 | 更早失败（GhidraApplicationLayout 找不到安装） |

**结论**：不是路径/ACL 的问题，是 Ghidra 12.2 在本机无法创建 Felix bundle 缓存
（`~/.ghidra` 一个文件都没写出来）。这条环境问题今天不追了。

**下一步（明确）**：消融实验改到 **VM 上跑**（VM 里的 Ghidra 此前成功产出过
d615 / d816 的 flow），模型通过 SSH 反向隧道接宿主机的 `fwmap serve`。

### 🔧 环境问题：Ghidra 恢复（今天的意外收获）

| 尝试 | 结果 |
|---|---|
| 手工建 `~/.ghidra` | 无效 |
| 重置安装目录 ACL | 无效（DENY 继承自 `C:\deepseek`，子目录改不动） |

| **重定向 `APPDATA`/`LOCALAPPDATA`** | **成功** ✅ |

`m2.py` 已把 `APPDATA`/`LOCALAPPDATA` 与 `TEMP` 一起指到工程旁的私有目录，
