# 实验记录：让 LLM 判断「鉴权」而不是「守卫」

- 日期：2026-11-09
- 目标固件：Edimax BR-6478AC v2 v1.23 / `bin/webs`（MIPS，888 KB）
- 输入：M3 保留的 27 条链（15 个函数）
- 脚本：`auth_exp.py`（一次性实验脚本，未进主流程）
- 原始数据：`auth_exp.json`

---

## 1. 为什么要做这个实验

工具现有流水线是**静态优先**的：M1/M2/M3 全是符号与数据流分析，LLM 只在最后回答一个问题——
「危险调用前有没有检查」。这个问题的答案，静态规则也能给，LLM 的边际价值很低。

因此提出假设：

> **如果把 LLM 的问题从「有没有守卫」换成「有没有鉴权」，它能不能提供静态规则给不了的信息？**

选鉴权做试点的理由：鉴权是**语义**（谁算已登录、哪个 cookie 有效、是否有前置过滤器），
固定词表覆盖不了——M2.5 在 Tenda 上跑出 `protected 0 / unprotected 25` 就是证据。

---

## 2. 方法

1. 取 M3 保留链涉及的 8 个函数；
2. 反编译后**压缩**：前 40 行 + 最多 45 行含安全关键词的行（`websGetVar`/`system`/`cookie`/`auth`…）；
3. 提示词要求模型三选一：`AUTHENTICATED` / `UNAUTHENTICATED` / `UNCLEAR`，并给出**证据行**；
4. **证据校验**：引用行必须能在反编译原文里逐字找到，否则标记为编造；
5. 结果与 M3 的危险链交叉：未鉴权 + 可达危险函数。

---

## 3. 结果

| 函数 | 判定 | 证据 | 说明 |
|---|---|---|---|
| formAutoFWupgradeIE | UNAUTHENTICATED | ✓ | 直接执行系统命令 |
| formStaDrvSetup | UNCLEAR | ✓ | 代码被截断 |
| formWlbasic | UNCLEAR | ✓ | 代码被截断 |
| wiz_5in1_redirect | UNCLEAR | ✓ | 代码被截断 |
| formiNICbasic | UNCLEAR | ✓ | 代码被截断 |
| getiNICIndex | UNCLEAR | ✗ | 证据编造 |
| formWIRESch | UNCLEAR | ✓ | 无法判断 |
| formTcpipSetup | UNCLEAR | ✓ | 代码被截断 |

**7/8 弃权，弃权理由全部指向「输入被截断」。**

### 交叉结果

唯一被判 `UNAUTHENTICATED` 的是 `formAutoFWupgradeIE`（`system` 强源）。
但该链此前已人工核实为**假阳性**——`sprintf` 的两个参数都是静态字符串常量。

---

## 4. 结论

### 4.1 模型行为可靠

- 8 条里 7 条证据真实（逐字命中原文），仅 1 条编造；
- 面对不完整输入，模型选择 `UNCLEAR` 而非硬编答案。

即：**保守性符合预期**，与 guard 复核任务上的表现一致。

### 4.2 但实验本身没有回答原问题

函数最大 2325 行，压缩到 ~85 行后，模型看到的是明显残缺的代码，
它诚实地弃权——**这是提示词设计的问题，不是模型能力的问题**。

因此本实验**未能证明**「LLM 能提供静态规则给不了的信息」，也**未能证伪**。

### 4.3 一个有效的副产物

「未鉴权」单独看没有意义：`formAutoFWupgradeIE` 确实没有鉴权，但它也没有可控输入。

> **鉴权维度必须与污点维度交叉**才有判别力：
> 未鉴权 × 可达危险函数 = 高优先级；任一单独使用都会放大假阳性。

---

## 5. 下一版设计（待实现）

1. **不再压缩**：直接送入 300–400 行（约 6k token，7B 模型可承载）；
   超长函数按基本块切分，分段提问后汇总，避免「截断」成为默认答案。
2. **问题收窄**：不问「有没有鉴权」，改为可判定的二选一：
   - 本函数是否调用鉴权相关函数？
   - 本函数是否读取 cookie / session / token？
3. **交叉输出**：`auth.py` 的结论与 `m3flow` 的链合并，输出「未鉴权且可达」清单，
   而不是单独给一张鉴权表。

## 7. v2：去掉截断 + 问题收窄（失败，但结论重要）

### 7.1 改动

| 项 | v1 | v2 |
|---|---|---|
| 输入 | 前 40 行 + 45 行关键词（约 85 行） | 按 300 行切块，块间 20 行重叠，最多 3 块 |
| 问题 | 「有没有鉴权」开放式 | 两个二选一：A) 有没有调用鉴权函数；B) 有没有读取 cookie/session/token |
| 汇总 | 单次判定 | 任一块命中即 AUTHENTICATED；全覆盖无命中则 UNAUTHENTICATED；否则 UNCLEAR |

脚本：`experiments/auth_semantics_v2.py`

### 7.2 结果

```
[1/4] formAutoFWupgradeIE  UNAUTHENTICATED  块失败: CUDA out of memory (10.99 GiB)
[2/4] formStaDrvSetup      UNAUTHENTICATED  块失败: CUDA out of memory (996 MiB)
[3/4] formWlbasic          UNCLEAR (未覆盖全)
[4/4] wiz_5in1_redirect    UNAUTHENTICATED  块失败: CUDA out of memory (4.20 GiB)
```

四个函数**全部出现块级 OOM**。

### 7.3 关键发现：7B 模型吃不下 300 行

300 行反编译代码约 6k token。模型权重只占 5.56 GB 显存，剩下的 KV cache 与激活值不足以承载 6k token 的输入，
直接触发 `CUDA out of memory`。

结论：**在本机硬件上「不截断」不可行**。实际可用预算约 **每块 100–150 行**。
这不是模型能力问题，是显存预算问题——换 24 GB 显卡可以放宽，但那就不是"本地小模型"的前提了。

### 7.4 同时暴露一个实现缺陷

块失败时未把 `covered` 置为 False，导致 3 个只读完部分块的函数被误判为 `UNAUTHENTICATED`。

> **读不完就必须是 UNCLEAR。** 否则这一层会系统性制造假阳性——比不做更糟。

### 7.5 v3 设计（待实现）

| 项 | v3 |
|---|---|
| 块大小 | 120 行（约 2.5k token），显存安全 |
| 块数 | 6–8，保证覆盖完整函数 |
| 失败处理 | 任一块失败 → 整体 UNCLEAR |
| 问题 | 保持二选一（A 鉴权调用 / B cookie 读取） |
| 输出 | 与 M3 危险链交叉，输出「未鉴权且可达」优先级清单 |

### 7.6 两版实验的共同结论

| 版本 | 失败原因 | 学到的 |
|---|---|---|
| v1 | 截断到 85 行 | 给少了，模型诚实弃权（不是判断力问题） |
| v2 | 块 300 行 | 给多了，显存装不下（不是能力问题） |

> **问题既不在模型判断力，也不在提示词措辞，而在「喂多少信息」这个工程参数上。**
> 可行区间：每块 100–150 行 + 多块覆盖 + 失败即弃权 + 与污点交叉。
