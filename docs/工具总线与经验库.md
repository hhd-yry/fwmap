# 工具总线 + 经验飞轮

> 2026-11-17 做的两件事。它们解决的是同一个问题：
> **工具不该每次都从零开始，也不该每接一个就要改一遍代码。**

## 一、经验飞轮（`fwmap/knowledge.py`）

### 为什么不是"训练模型"

我们手上的样本是个位数固件、几百条链，既没有 ground truth（哪条链真可利用），也没有规模。
训练在这里只会过拟合到见过的厂商。真正稀缺的不是模型容量，是**记忆**。

### 三个库（明文 JSON，可人工编辑）

| 文件 | 内容 | 谁写 |
|---|---|---|
| `vendors.json` | 厂商画像：用哪种机制找路由、抽了多少条、跑过几次 | `discover` / `triage` |
| `lessons.json` | 经验卡：被证伪的判断（同句去重，只加 hits） | 各处失败路径 |
| `stats.json` | `机制 × 厂商` 的成功/失败计数 | `discover` |

默认落在 `~/.fwmap/knowledge/`，可用 `FWMAP_KNOWLEDGE_DIR` 覆盖。

### 行为变化

```
跑之前查画像 → 命中就跳过探索（实测：第二次跑 Edimax 直接命中 page_derived）
跑之后写回  → 包括"为什么失败"（假崩溃、参数名不对、M2 没对上 handler）
报告里      → 多一行「经验库：厂商 X · 命中历史 · 本轮新增 N 条」
```

### 两条纪律

1. **没验收过的经验照样用，但标明「仍会验收」** —— 记忆不能替代证据
2. **厂商键不能用泛称**：`.../d615/root` 要认成 `d615`，否则所有固件撞成 `root`

```bash
fwmap knowledge            # 看记住了什么
fwmap knowledge --json     # 原始数据
fwmap knowledge --reset all
```

## 二、工具总线（`fwmap/toolbus.py`）

### 铁律

> **没有成功判据的工具，不许注册。**

`Tool(...)` 的构造函数会直接拒绝。这条是 `fwupdate.cgi` 那次的教训：
工具说"跑完了"不算，代码得能自己验。

### 怎么加一个工具（不用改总线）

```python
toolbus.register(Tool(
    "sasquatch", "unpack",
    ["sasquatch", "-f", "-d", "{out}", "{src}"],
    success=validate_rootfs,          # 必填：怎么判断它真成了
    note="补丁版 unsquashfs，专读老版本 squashfs",
))
```

三类验收形态：

| 形态 | 用于 | 例子 |
|---|---|---|
| `success(outdir)` | 产出文件的工具 | 解包：目录像不像 rootfs |
| `stdout_success(text)` | 产物是输出的工具 | readelf：有没有解析出 Machine |
| `python=fn` | 纯 Python 工具 | uimage 去头、lief 解析 |

### 现在有什么（26 个）

```
unpack  10：7z binwalk unblob unsquashfs sasquatch cramfsck ubireader jefferson gzip cpio
decrypt  8：uimage trx netgear-chk gzip-stream xz-stream bzip2-stream lzma-stream zlib-stream
analyze  4：readelf rabin2 rizin lief
emulate  4：qemu-system-mips / mipsel / arm / aarch64（按 profile 启动）
```

### 两个关键设计

1. **carve**：自动切内嵌文件系统（扫前 8 MB 找 `hsqs`/`sqsh`/`shsq`/`CRAM`/`UBI#`）
   —— 以前要手工 `dd bs=1M skip=1`，现在自动做
2. **魔数排序**：`_PREFER` 表让"文件头指向的工具"排在前面（uImage → uimage，
   gzip → gzip-stream）。模型可以给顺序，但**文件头说话更算数**

### 外部脚本挂载点

厂商解密脚本不用改代码，写个 JSON 就行：

```json
[{"name": "dlink-cr6b",
  "cmd": ["python3", "/opt/cr6b.py", "{src}", "{out}"],
  "capability": "decrypt",
  "success": "magic"}]
```

```bash
fwmap extract fw.bin -o out --capability decrypt --external tools.json
```

**脚本质量再差也不怕**：它必须过同一套验收，解不开就是解不开。

## 三、命令一览（本次新增）

```bash
fwmap knowledge [--json] [--reset ...]      # 经验库
fwmap extract <镜像> -o <目录> [--capability unpack|decrypt] [--external tools.json]
fwmap analyze <binary> [--tool readelf]     # 静态分析
fwmap emulate <镜像> -o <目录> --profile p.json   # 全系统模拟
```
