# 2026-11-25：探针加固、DIR-615 崩溃候选、以及一次真实的 fork 炸弹

## 一、DIR-615 的 `/login.cgi` 崩溃（新的候选）

### 现象

```
GET /login.cgi                    → 0 字节，httpd 进程被 SIGSEGV 打死
GET /login.cgi?graph_id=1         → 1818 字节，200 Ok，服务存活
GET /login.asp                    → 3258 字节，200 Ok
POST /login.cgi（无 graph_id）     → 0 字节，进程崩溃
```

### 复现数据（每次重新起服务）

| 次数 | 请求 | 字节 | 状态 | 服务存活 |
|---|---|---|---|---|
| 1 | GET /login.cgi | 0 | no-crash | 是 |
| 2 | GET /login.cgi | 0 | **crash** | **否** |
| 3 | GET /login.cgi | 0 | **crash** | **否** |
| 4 | GET /login.cgi?graph_id=1 | 1818 | no-crash | 是 |
| 5 | GET /login.cgi?graph_id=1 | 1818 | no-crash | 是 |

**与输入相关**：带 `graph_id` 就不崩 → 不是环境缺失导致的假崩溃（对照组的教训用上了）。
一个**未认证的 GET 请求即可让 Web 服务退出**，属于可用性影响（DoS）。

### 查重

| 查询 | 命中 | 说明 |
|---|---|---|
| `DIR-615 login.cgi` | CVE-2017-9542 | 是**认证绕过**（modified POST），不是崩溃 |
| `DIR-615 graph_id` | 0 条 | 没有相关记录 |
| `DIR-615 denial of service` | CVE-2017-7404 | CSRF 类，与本题无关 |

**结论：目前未发现覆盖「未带 graph_id 导致 login.cgi 崩溃」的公开记录**，
可作为"未报告目标上的候选"；但它只是 DoS，写论文时按 DoS 定位，不要夸大成 RCE。

## 三、一次真实的 fork 炸弹（工具安全问题）

### 发生经过

测 Edimax 的 `bin/webs`（Boa）时，之前误把 `usr/sbin/httpd`（busybox 符号链接）
当服务启动，并用 `-h /web -p 80` 请求页面。结果 busybox httpd 把自己当 CGI 再执行，
形成链式自我复制：

```
busybox httpd → fork → busybox(作为CGI) → fork → busybox → ...
```

**虚拟机上滚到 508 个 busybox 进程、load average 513**，SSH 一度不可用。

### 根因

不是固件的问题，是**"在宿主机上直接跑不可信程序"的必然风险**。
以前只按单个请求超时控制，没有限制进程数。

### 修复

`fwmap/dyn.py` 增加资源围栏：

```python
def _child_limits():
    resource.setrlimit(resource.RLIMIT_NPROC, (64, 64))   # 最多 64 个进程
    resource.setrlimit(resource.RLIMIT_CPU, (120, 120))   # 最多 120 秒 CPU
```

所有服务启动（`run_request` 与 `ServiceSession`）统一走 `_popen_kwargs()`，
子进程继承这两个上限。

### 验证

同一台固件、同一个 busybox httpd、连打 6 次请求：

```
起始 busybox 进程: 0
  第1次  183B → 1
  第2次  183B → 1
  第3次 4096B → 1
  ...
停止后: 0
```

**进程数被钉死在 1，宿主机安全了。**
