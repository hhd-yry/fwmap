## 三、怎么读结果

先看 `C:\deepseek\tmp\low-m\results.jsonl` 里的 `tool_calls_used`：

| 值 | 含义 |
|---|---|
| **2** | 预算生效（这是必须的；若还是 4，说明修没生效，回来查 `runner._run_interactive_subject` 的 limits 合并顺序） |
| 其他 | 异常，先别解读 |

再看 `cases\c081\submission.json`：

```json
{"claim": "...", "citations": ["e?"], "claim_source": "model"}
```

| 结果 | 解读 |
|---|---|
| `claim=exited, citations=[e2]` | ✅ **模型读得巧**：2 次调用里先读到了正确记录，引文也对 |
| `claim=exited, citations=[e4]` | ❌ 结论对但**引错对象**（e4 是 svc-71）→ `citation_unsupported`；说明它是"抄第一条的状态" |
| `claim=running` | ❌ 被 e3 带偏（时间是 10:01） |
| 无 submission / abstained | 没提交，看 `events.jsonl` 最后几步 |

再对照 `events.jsonl` 的读取顺序（`decision` 的 `action`）：

```
read:e4 → read:?  ...   ← 前两条读了谁，决定它是否"读得巧"
```

## 四、必须一并记录的三件事

3. **是否错引**（`failure` 字段是不是 `citation_unsupported`）。

## 七、如果结果不理想（也是合格结果）

- 若模型在 2 次预算里**必然读错**，说明它"读得多"而非"读得巧"——这同样可写进论文，
  配合"时间错位"那对（读全部时能对）形成对比；
- 把结论写成："模型在充裕预算下能答对时间错位任务；在 2 次预算下未能挑中正确记录"，
  并给出它与规则的成本/正确率对照表。
