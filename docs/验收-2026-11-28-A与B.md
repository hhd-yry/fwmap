## 一、修掉的三个缺陷

这三条都是**会改变结论**的缺陷：工具会把"没做成"报成"做成了"，
把"观测到空响应"写成"确认崩溃"。修之前先写了回归用例，确认它们真的失败。

| # | 缺陷 | 修之前的表现 | 修之后 |
|---|---|---|---|
| 1 | 有执行轨迹就返回 0 | 空目录 + 一步预算，`ok=False`、候选 0、结论 0，退出码 **0** | 按 `status` 给码：未完成 **非 0** |
| 2 | 关模型仍记一次兜底 | `fallback_steps = 总步数 − 模型步数`，主动关模型也得 1 | 拆成 `model_steps` / `rule_steps` / `fallback_steps` |
| 3 | 空引用仍生成强结论 | `evidence: []` 时校验循环一次不进，直接接受 `crash` | 空引用、引用别的对象、数值对不上，**一律拒绝** |

## 二、完成状态与退出码

`loop.run()` 结果新增 `status` / `stop_reason` / `pending` / `handoff`。
CLI 退出码：

| 退出码 | 状态 | 含义 |
|---|---|---|
| **0** | `completed` | 已按预期收工（**零发现也算完成**） |
| **2** | `budget_exhausted` / `no_progress` / `failed` | 未完成：预算用尽 / 无进展 / 一步没跑成 |
| **3** | `dependency_missing` | 请求了探针，但本机没有 qemu/chroot |
| **4** | —— | 结果写不出去（JSON 或 handoff） |

**判定顺序**（写死在 `run()` 末尾）：

1. 一步都没执行 → `failed`（若请求了探针则 `dependency_missing`）
2. 最后一步是 `done` → `completed`
3. 触发无进展检测 → `no_progress`
4. 请求了探针但不可用 → `dependency_missing`
5. 其余 → `budget_exhausted`

**无进展检测**：连续 3 步「候选数 / 可审计证据数 / 结论数」都没变化就停，
不再继续烧预算。

## 三、证据强度分开写

`verdict` 现在记录三样，不再混成一个 `crash`：

```json
{
  "uri": "/login.cgi",
  "kind": "crash",
  "support": "observed-only",      // 或 process-exit
  "citation_source": "model",      // 不再有程序补录
  "evidence": ["/login.cgi 0B unknown"],
  "measured": {"len": 0, "verdict": "unknown", "status": null}
}
```

- `support = observed-only`：只有空响应，**进程状态未确认**；
- `support = process-exit`：探针记录里另有进程退出的独立记录；
- 报告与 `handoff.md` 都会把这两个说法分开印出来。

DIR-615 那条个案在文档里有模拟器信号和跨版本记录，证据强于单条空响应，
所以报告里的等级仍是 **candidate**，不下调也不上调。

### 引用校验的三条规则

1. 必须至少引用一条，**空引用直接拒**；
2. 每条引用必须提到**结论对象本身**的 uri（引用别的对象不算）；
3. 引文里出现的长度必须与实测一致（`0B` 就得是 0 字节）。

窄问题分支**不再替模型补引用**（旧版会在模型没给列表时由程序编一行），
没有就返回空，让校验去拒。

## 四、归因口径

| 字段 | 含义 |
|---|---|
| `model_steps` | 模型选定的动作，且被执行 |
| `rule_steps` | 模型**主动关闭**时的规则步（不是兜底） |
| `fallback_steps` | 模型尝试过但被拒/失败，由规则顶上 |
| `rejects` / `reject_kinds` | 被拒次数与原因分布 |
| `verdict_tried` / `verdict_accepted` | 尝试下结论次数 / 规则接纳次数 |
| `verdict_accept_rate` | **没有尝试时为 `null`**，界面显示"不适用"，不再显示 0 |
