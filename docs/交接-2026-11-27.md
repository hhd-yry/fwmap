## 一、项目是什么

**fwmap** —— 面向物联网固件的端到端自动漏洞挖掘工具，本科毕业论文配套系统。

论文题目：《fwmap：面向物联网固件的端到端自动漏洞挖掘方法》

**核心方法论**：规则执行、模型取证、证据裁决。

- 规则负责：穷举（把端点都列出来）、验收（判对错）、兜底（模型答不出时）
- 模型负责：借语义线索挑目标、把观察写成结论
- 硬约束：模型可以判断，但**不能凭空断言**（结论必须引用实测证据）

| 自评表（参与率 / 被拒 / 结论采纳率） | ✅ | 跑完自动输出 |

### 2.2 明确做不到的（别再花时间试）

| 做不到 | 证据 |
|---|---|
| 让 1.5B 自由选动作 | 连跑 6 步一次没选过 `probe`，全被规则兜底 |
| 让模型从"行为"发现异常 | 藏掉端点名字后，判出率 **0/5**（具名 5/5） |
| 模型自己写新工具 | 不现实，动作空间可扩展、工具本身要人写 |

### 2.3 关键数据（写论文可直接引用）

| 实验 | 设置 | 结果 |
|---|---|---|
| 具名 temp=0.0 ×5 | DIR-615，预算 8 步 | 5/5 判出崩溃（逐位相同 = 贪心解码必然） |
| 具名 temp=0.7 ×5 | 同上 | **5/5**，参与率 75→78%，结论稳定 |
| **匿名 temp=0.7 ×5** | 隐藏 uri 与参数 | **0/5**，挑的全是清单最前面几条 |
| 自评 | 单次运行 | 模型完成 6/8 步（75%），被拒 2 次，结论核验 1/1 |

**结论一句话**：模型挑端点的能力全部来自**名字和参数**这类语义线索；抽掉线索，
它就退化成顺序挑 —— 和固定规则没有区别。

## 四、下一步任务：P0（可以立刻开工）

> 计划日期：**2026-11-27 ~ 11-28**
> 目标一句话：**让人不在的时候，工具不会骗人。**

### 4.1 为什么先做这个

现在的 agent 循环里，模型答不出来就**静默退回规则**，流程照样跑完、报告照样完整。
如果人不在，没人知道那一步是模型没做成。**这不是自主，是伪装。**

### 4.2 三件事

#### ① 兜底留痕

现状：`_decide()` 退回 `_heuristic` 时只在 log 里打了一行，产物里已有 `source` 字段，
但**没有汇总**。

要做：
- 报告头部输出一行总结，例如
  `模型完成 6/8 步，规则兜底 2 步（原因：多余参数 1、重复动作 1）`
- 已有 `_summarize()` 产出 `model_share` / `reject_kinds`，接上即可。

**判据**：任何一份报告，都能一眼看出哪些结论是模型下的、哪些是规则下的。

#### ② 卡住检测（替代"重复动作"补丁）

现状：只有"同一动作同样参数重复就换"的补丁，不是真正的进展度量。

要做：连续 N 步满足以下任一 → 判定卡住
- 没有新候选端点
- 没有新证据
- 结论数为 0

卡住后**停止，不烧预算**。

**判据**：预算耗尽时一定有一份交接包，而不是一个"看起来跑完了"的报告。

#### ③ `handoff.md`

跑完（正常结束或卡住）都写一份：

```markdown
# 交接：<固件名> <时间>
## 已经确认的
## 还没确认的
## 卡在哪 / 建议下一步
```

**退出码非 0**（让 CI / 批处理知道这条没跑完）。

### 4.3 涉及文件

- `fwmap/agent/loop.py` —— 主改
- `fwmap/agent/loop_cli.py` —— 输出与 exit code
- `tests/test_agent_loop.py` —— 新增检查

### 4.4 红线（不要破坏）

1. **`source` 字段不能去掉** —— 没有它，"自我进化"无法归因；
2. **不能让模型改规则** —— 模型可以建议换策略，改 `_heuristic`、改验收条件必须人审；
3. **测试必须全绿** —— 40 套测试，agent 循环 41 项检查；
4. **不要为了"跑通"而放宽证据校验** —— verdict 的引用校验是这套东西的立身之本。

## 六、环境与命令速查

### 6.1 验证环境正常

```bash
cd <repo>
python -m pytest tests -q        # 或逐个跑：python tests/test_agent_loop.py
python -m fwmap plan --help      # 应看到 --probe / --temperature / --anonymize
```

### 6.2 agent 循环

```bash
python -m fwmap plan <binary> --rootfs <rootfs> \
  --probe              # 真把端点发给固件（要 Linux + qemu-user）
  --temperature 0.7    # 0=贪心可复现，>0=采样测鲁棒性
  --anonymize          # 隐藏 uri 和参数（测"靠名字还是靠行为"）
  --max-steps 8 \
  --json /tmp/plan.json
```

跑完自动输出：参与率 / 被拒次数与原因 / 探测与异常数 / 结论采纳率。

### 6.3 两台机器分工（模型在宿主机显卡，qemu 在 VM）

```bash
# 宿主机
python -m fwmap serve --port 11434          # 模型挂成 OpenAI 兼容接口
python lab/llm_tunnel.py                    # 反向隧道（VM 的 sshd 转发回来）

# 宿主机：同步仓库到 VM
python lab/vm_sync.py

# 在 VM 里跑
python lab/vm_put_run.py lab/plan_d615.sh "bash"
```

> `lab/*.py` 里硬编码了 lab VM 地址口令（`192.168.8.137` / `ubuntu` / `ubuntu`），换环境先改。

### 6.4 两个踩过的坑

1. **隧道里不能给 socket 设 timeout**：模型一次推理 20 秒以上，超时会把连接关掉，
   服务端回包报 `WinError 10053`；
2. **`vm_sync.py` 要先 `sudo rm -rf` 目标目录**：上一轮用 sudo 跑，目录里是 root 的文件。

## 七、候选漏洞（可以独立推进）

**D-Link DIR-615 `GET /login.cgi` 未认证崩溃**

| 项 | 状态 |
|---|---|
| 受影响 | C2 3.03（2010-10）、E4 3.08（2011-08），MIPS BE |
| 触发 | `GET /login.cgi`（不带 `graph_id`），单请求，无需认证 |
| 本地复现 | ✅ 3/3（qemu-user + chroot），三对照排除环境因素 |
| 跨版本 | ✅ 两个硬件修订；2015 版接口已不存在（404） |
| 公开查重 | ⚠️ 仅离线 NVD（423,984 条）：`DIR-615 graph_id` 0 命中 |
| 真机 / 厂商确认 | ❌ 未做 |
| **证据等级** | **candidate（候选）**，不是"复现"，也不是"新漏洞" |

复现：`sudo bash tools/poc-dir615-login-cgi.sh /home/ubuntu/lab/d615/root`

**最值得做的一步**：反汇编 `sbin/httpd` 找根因，把报告从「某请求导致崩溃」
升级成「第 X 条指令对空指针解引用」。预期是 `websGetVar(wp, "graph_id", NULL)`
返回 NULL 后未判空。
