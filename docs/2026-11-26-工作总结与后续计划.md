## 一、今天完成了什么

### 1.1 一句话概括

把模型从"流水线里解释别人的结果"变成"自己看、自己挑、自己判"，
然后用三组对照实验测出它的能力边界在哪。

### 1.2 具体改动

| 模块 | 改动 | 验证 |
|---|---|---|
| `fwmap/agent/loop.py` | `probe` 接通固件探针；候选端点与参数进状态 | DIR-615 实跑 |
| 同上 | 新增 `source` 字段（model / heuristic），谁做的决定可分辨 | 发现前一轮"模型挑的"全是规则兜底 |
| 同上 | **受限决策**：阶段由规则收束，端点由模型挑 | 1.5B 从"6 步选不出 probe"变成可用 |
| 同上 | 新增 `verdict` 动作 + **证据裁决**（引用必须真实、结论不能与实测矛盾） | 模型判出 `/login.cgi` 崩溃 |
| 同上 | 自评表：参与率 / 被拒原因 / 结论采纳率 | 5 次连跑一致 |
| 同上 | `--anonymize`：隐藏 uri 与参数 | 名字/行为对照实验 |
| `fwmap/routes.py` | 探针带回响应首行（`snippet`） | 模型下结论时有引用材料 |
| `fwmap/agent/loop_cli.py` | `--temperature`、`--anonymize`、自评输出、结论输出 | CLI 验证 |
| `tools/poc-dir615-login-cgi.sh` | 一键取证脚本（对照 A/B + 3 次触发） | VM 实测 3/3 |

### 1.3 中途被自己的流程坑了三次（都修了）

1. 进入"挑端点"阶段后，`verdict` 分支**永远触发不到** → 模型被锁死在 probe 循环；
2. 模型把结论下到正常页（判 normal），**回避真正 0 字节那条** → 规则限定只能对异常条目下结论；
3. `pages {'url': ...}` 这种**编参数被静默接受** → 改成多余参数直接判非法。

> 教训：说"模型不会做事"之前，先确认流程有没有给出口。

## 二、四组关键数据

| 实验 | 设置 | 结果 |
|---|---|---|
| 具名 temp=0.0 | 5 次，预算 8 步 | **5/5** 判出 `/login.cgi` 崩溃（逐位相同） |
| 具名 temp=0.7 | 5 次 | **5/5**，参与率 75→78%，handler 3–4（路径有波动，结论稳定） |
| **匿名 temp=0.7** | 隐藏 uri 与参数 | **0/5**，挑的全是候选清单最前面几条 |
| 自评 | 单次运行 | 模型完成 6/8 步（75%），被拒 2 次，结论核验 1/1 |

**结论一句话**：

> 模型挑端点的能力全部来自**名字和参数**这类语义线索；抽掉线索，
> 它就退化成顺序挑 —— 和固定规则没有区别。

同时：`temp=0` 下的"5/5 完全一致"是贪心解码的必然，**不能当鲁棒性证据**；
真正的鲁棒性证据是 `temp=0.7` 下仍然 5/5。

## 三、候选漏洞：DIR-615 `/login.cgi` 未认证崩溃

### 3.1 当前状态

| 项 | 状态 |
|---|---|
| 类型 | 拒绝服务（Web 服务崩溃），**不是 RCE** |
| 受影响 | DIR-615 **C2 3.03**（2010-10）、**E4 3.08**（2011-08），MIPS BE |
| 不受影响 | A(A1A) 2.5.12（2015-05）：接口已不存在，返回 404 |
| 触发 | `GET /login.cgi`（不带 `graph_id`），单请求 |
| 认证 | 不需要 |
| 本地复现 | ✅ 3/3（qemu-user + chroot） |
| 跨版本 | ✅ 两个硬件修订 |
| 环境排除 | ✅ 三对照（正常页 / 带参数 / 随机路径） |
| 公开查重 | ⚠️ 仅离线 NVD（423,984 条）：`DIR-615 graph_id` 0 命中 |
| 真机验证 | ❌ 无设备 |
| 厂商确认 | ❌ 未提交 |

**证据等级：candidate（候选）** —— 不是"复现"（没参考任何公开 PoC），
也还不能叫"新漏洞"（未真机、未查遍、未确认）。

### 3.2 怎么自己跑（10 分钟）

```bash
cd ~/fwmap-run
sudo bash tools/poc-dir615-login-cgi.sh /home/ubuntu/lab/d615/root
```

预期输出：

```
GET /index.asp            → 305 字节   进程=up      ← 服务本来活着
GET /login.cgi?graph_id=1 → 1818 字节  进程=up      ← 带参数正常
GET /login.cgi            → 0 字节     进程=down    ← 就这一下
```

`httpd.log` 里有：`qemu: uncaught target signal 11 (Segmentation fault) - core dumped`

详细步骤（含手动单发、常见失败、跨版本复测）见
`docs/2026-11-26-今日汇总与复现手册.md` 第二部分。

### 3.3 升级成"漏洞"还差三步

1. 在线渠道全查（NVD 在线 / Exploit-DB / CNVD / 厂商公告）；
2. 真机或 FirmAE 全系统模拟，排除 qemu 因素；
3. 提交 D-Link 安全响应 / CNVD / MITRE CNA。

### 3.4 最值得先做的一步：找根因

现在只知道"崩了"，不知道为什么崩。反汇编 `sbin/httpd`、定位 `/login.cgi` 的 handler，
预期是 `websGetVar(wp, "graph_id", NULL)` 返回 NULL 后未判空。

**做完能把报告从「某请求导致崩溃」升级成「第 X 条指令对空指针解引用」**，
而且大概率能找到同一二进制里犯同样错的其它 handler。

## 四、当前架构的三个问题

| 问题 | 现状 | 后果 |
|---|---|---|
| **兜底静默** | 模型失败 → 规则顶上 → 不留痕 | 报告把规则的功劳算成模型的，人不在时无从发现 |
| **动作空间写死** | `ACTIONS` 5 个，工具总线有 **30 个工具** | "让模型控制工具"无从谈起 |
| **经验不回流** | `knowledge.py` 只用于排序，不进提示 | 同样的坑，下一台固件再踩一遍 |

> 现在的瓶颈不是模型不够强，是**它看不到东西、它的失败没人记、它能动的工具只有 5 个**。
> 换更强的模型，只会让"它看不到东西"这件事更贵。

## 五、后续计划

### 5.1 设计原则

> **规则干得了的，不让模型干；规则干不了的，必须模型干。**
> 但边界不写死 —— 每个决策点做成可开关的策略，跑对照实验，让数据决定谁来做。

三种策略可随时切换：`always_rule` / `always_model` / `model_then_rule`。
比较**成功率 / 步数 / 兜底率**，换模型后重跑，边界自己移动。

### 5.2 三层"进化"，说清哪层能自动

| 层 | 内容 | 能自动吗 |
|---|---|---|
| L1 策略 | 用谁做、温度、预算，由历史数据决定 | ✅ |
| L2 经验 | 失败 → 教训 → 下次进提示 | ✅ |
| L3 能力 | 动作空间从 toolbus 生成 | ⚠️ 半自动（工具本身仍需人写） |

**"自我进化"的现实定义**：策略与经验自进化，能力集靠人扩。
不要承诺"自己写新工具"。

### 5.3 分阶段计划（含日期）

| 阶段 | 日期 | 目标 | 判据 |
|---|---|---|---|
| **P0 诚实降级** | 11-27 ~ 11-28 | 兜底留痕 + 卡住检测 + `handoff.md` | 预算耗尽必有交接包；任何报告能看出哪步是规则替模型做的 |
| **P1 观察层** | 11-29 ~ 12-01 | 把响应差异 / 状态码 / "与对照组比属于哪类"喂给模型 | 匿名组 0/5 → ≥3/5 |
| **P2 决策点参数化** | 12-02 ~ 12-05 | 三策略可切换 + 对照实验 | 边界由实验数据决定，不靠拍脑袋 |
| **P3 经验回灌** | 12-06 ~ 12-10 | 教训进提示（不只进排序） | 同类固件第二次跑，重复失败归零 |
| **P4 动作空间生成** | 12-11 ~ 12-15 | `ACTIONS` 由 toolbus 30 个工具动态生成 | 组合出 ≥2 条未硬编码的调查路径 |
| **论文整合** | 12-16 ~ | 五组数据进实验章 | 职责边界一节有数据支撑 |

**顺序理由**：P0、P1 都不依赖模型变强，但现在就在拖后腿 —— P0 决定工具可信不可信，
P1 决定模型有没有材料可推理。P4 最后做，因为它最容易被误当成"智能"。

### 5.4 人不在时必须有的三样

1. **诚实降级**：规则替模型做的每一步都留痕；
2. **卡住求助**：连续 N 步无新候选 / 无新证据 / 结论为 0 → 停，不烧预算；
3. **交接包 `handoff.md`**：已确认的 / 还没确认的 / 卡在哪 + 建议下一步。

### 5.5 护栏（答辩必被问）

1. 模型可以**建议**改策略，但改规则、改验收条件必须人审 —— 否则实验无法复现；
2. 经验库要按命中率定期淘汰，只进不出会越积越脏；
3. `trace` 必须带 `source`，否则"自我进化"无法归因。

## 附：本次新增命令行

```bash
fwmap plan <binary> --rootfs <dir> \
  --probe              # 真把端点发给固件（要 Linux + qemu）
  --temperature 0.7    # 0=贪心可复现，>0=采样测鲁棒性
  --anonymize          # 隐藏 uri 和参数（测"靠名字还是靠行为"）
  --max-steps 8
```

跑完自动输出：模型参与率 / 被拒次数与原因 / 探测与异常数 / 结论采纳率。
