# 融合对接指南：把你的工具接进 fwmap

> 给做另一半工具的同学看。
> 目标：**你不改你工具的代码，我不改我的**，两边各自发版，最后能在一个流程里一起跑。

---

## 0. 三十秒版本

```bash
# ① 生成模板（会给你 manifest.json + tool.py + README.md）
python -m fwmap plugin init ./my_plugin --name my_tool --desc "我的工具干什么"

# ② 改 tool.py 里的三段（参数 / 逻辑 / 输出 JSON），再跑一遍看看
python ./my_plugin/tool.py --target <某个 rootfs 目录>

# ③ 自测能不能接进来
python -m fwmap plugin test ./my_plugin/manifest.json --target <某个 rootfs 目录>

# ④ 在智能体流程里用它
python -m fwmap autopilot <rootfs> --plugin ./my_plugin/manifest.json
```

第 ③ 步看到 `[OK] 接口通了` 就算接上了。

## 1. 我们需要你提供什么

**一句话：一条能在命令行跑起来的命令，参数里有一个"目标路径"，输出是 JSON。**

就这三样，别的都不用管：

| 我们需要 | 例子 |
|---|---|
| 一条命令 | `python my_tool.py --target /path/to/rootfs` |
| 参数里的占位符 | 把 rootfs 路径写成 `{target}` |
| JSON 输出 | `{"findings": [...], "count": 3}` 打到 stdout |

**你的工具内部怎么实现、用什么语言、跑多久，我们都不关心。**

---

## 2. manifest 字段详解

`manifest.json` 就是一张"说明书"，字段只有七个：

```json
{
  "name": "my_tool",
  "desc": "一句话说明这个工具干什么",
  "cmd": ["python", "C:/tools/my_tool.py", "--target", "{target}"],
  "args": {"target": "解包后的 rootfs 目录"},
  "output": "json",
  "timeout": 600,
  "cwd": null
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `name` | ✅ | 工具名，注册后叫 `plugin.<name>` |
| `cmd` | ✅ | **字符串数组**，不是一整条 shell 字符串 |
| `desc` | — | 一句话，会出现在 `fwmap tools` 里给模型看 |
| `args` | — | 参数说明 `{参数名: 说明}`，也是模型的参考 |
| `output` | — | `json`（默认）或 `text` |
| `timeout` | — | 秒，默认 600，超时会杀掉 |
| `cwd` | — | 子进程的工作目录，默认继承 |

### `cmd` 的占位符规则

`cmd` 里所有字符串都会被 `{参数名}` 替换：

```json
"cmd": ["python", "scan.py", "--root", "{target}", "--depth", "{depth}"]
```

调用时如果只传了 `target`、没传 `depth`，会直接返回
`参数没提供：'depth'` —— **不会带着半截参数去跑你的程序**。

### 为什么 `cmd` 必须是数组

因为要**避免 shell 注入**。写成数组，参数原样传给子进程；
写成一整条字符串，就得过一遍 shell，路径里有空格或者分号就出事。

## 3. 输出约定

### 方式 A：`"output": "json"`（推荐）

stdout 打一个 JSON，**dict 或 list 都行**：

```json
{"count": 12, "findings": ["...", "..."], "note": "一句话"}
```

我们只取**摘要**，不会把你几十 MB 的结果塞给模型：

```
[外部] my_tool：返回对象（count=12、tool=my_tool）
```

`data` 字段里只留标量（字符串截到 80 字），嵌套结构一律不往里塞。

### 方式 B：`"output": "text"`

stdout 打纯文本，我们取首行 + 行数：

```
[外部] my_tool：37 行输出，首行：Found 3 candidate endpoints
```

### 出错怎么办

**非 0 退出 = 失败**，stderr 会带回来：

```
[外部] my_tool 退出码 3：target 不是目录：/nope
```

我们不会因为你失败就中断整个流程，只是把这一步标成失败，继续走下一步。

## 4. 接进来之后长什么样

`autopilot` 会把它当成一个和内置工具平级的工具来调度：

```
[plugin] 已加载 demo_scan：演示用外部工具
[autopilot] 目标 rootfs：C:\deepseek\fw\p5\root
[1] (规则) 先确认解包完整        → check   ← 有问题（阻断 1 项）
[2] (规则) 还没选目标            → scan    ← 78 个 ELF，最高分 87（bin/webs）
[3] (规则) 调外部工具 plugin.demo_scan（融合的关键：能调别人做的东西）
     → plugin.demo_scan
     ← [外部] demo_scan：返回对象（tool=my_tool、files=1030）
...
```

**括号里的「(规则)/(模型)」标明这一步是谁定的**，你贡献的那一步也会在这条日志里。

也可以用 `fwmap tools` 看清单：

```

  ...
  plugin.demo_scan
    演示用外部工具：统计文件数
      - target: 解包后的 rootfs 目录
```

## 5. 五个常见坑

| 坑 | 症状 | 解法 |
|---|---|---|
| **路径写死** | 换台机器就失败 | `cmd` 里用 `{target}`，别写绝对路径；程序本身用相对路径或参数 |
| **中文乱码** | `UnicodeDecodeError` | 输出统一 **UTF-8**；Windows 上别用 GBK 打中文 |
| **往 stdout 打日志** | JSON 解析失败 | 日志走 **stderr**，stdout 只留 JSON |
| **超时** | `my_tool 超时（>600s）` | manifest 里加大 `timeout`，或者先在小样本上跑 |
| **退出码** | `退出码 3：...` | 成功必须 `return 0`；部分成功也返回 0，把细节写进 JSON |

---

## 6. 我们这边的三条保护（你可以放心）

1. **只取摘要**：你输出多大都行，进模型的只有一句话 + 几个数字；
2. **超时必杀**：超过 `timeout` 直接终止，不会卡住整个流程；
3. **失败不穿透**：你挂了只是这一步标红，流程继续走别的工具。

反过来说，**我们也不会替你解释你的结果** —— 摘要只报事实
（「跑了 / 多少条 / 前几项」），不做价值判断。

## 7. 一个完整例子

### ① 生成

```bash
$ python -m fwmap plugin init ./demo --name demo_scan --desc "统计文件数"
[+] 模板已生成：C:\deepseek\tmp\demo-plugin
    manifest.json  改 cmd / args
    tool.py      改逻辑（① 参数 ② 逻辑 ③ 输出 JSON）
    README.md      三步说明
```

### ② 生成的 tool.py（三段注释就是你要改的地方）

```python
def main() -> int:
    ap = argparse.ArgumentParser()
    # ① 这里定义你的参数
    ap.add_argument("--target", required=True)
    a = ap.parse_args()

    # ② 这里换成你的真实逻辑
    files = sum(len(f) for _, _, f in os.walk(a.target))

    # ③ 结果用 JSON 打到 stdout
    json.dump({"tool": "my_tool", "files": files, "findings": []}, sys.stdout,
              ensure_ascii=False)
    return 0
```

### ③ 自测

```bash
$ python -m fwmap plugin test ./demo/manifest.json --target C:\deepseek\fw\p5\root
[1/3] manifest 合法：demo_scan（统计文件数）
[2/3] 已注册为工具 `plugin.demo_scan`，开始试跑 …
[3/3] 返回：[外部] demo_scan：返回对象（tool=my_tool、files=1030）
      摘要数据：{"keys": ["tool", "files", "findings"], "head": {...}}

[OK] 接口通了。把它加进智能体：
     python -m fwmap autopilot <rootfs> --plugin .../manifest.json
```

### ④ 用

```bash

```

## 8. 如果你的工具不是"一条命令"

三种情况都能接：

| 你的工具形态 | 怎么接 |
|---|---|
| **Python 脚本 / 可执行文件** | 直接写进 `cmd` |
| **远程 HTTP 服务** | 写 10 行脚本 curl 一下，把 JSON 转出来，再挂进 `cmd` |
| **只能人工跑** | 那接不了自动化；但你可以把输出存成 JSON，用脚本包一层 |

远程服务的包装示例：

```python
# wrapper.py
import json, sys, urllib.request
target = sys.argv[sys.argv.index("--target") + 1]
r = urllib.request.urlopen(f"http://your-svc/scan?path={target}")
json.dump(json.load(r), sys.stdout, ensure_ascii=False)   # 转成 stdout
```

manifest 里 `cmd` 指向 `wrapper.py` 即可。
