# 架构：从「我用规则兜底」到「模型自己判断」（2026-11-26）

> 背景：后面会换更强的模型。目标是模型控制各种工具完成挖掘，规则能干的不让模型干，
> 规则干不了的必须模型干。现实约束：**人不盯着的时候，工具不能骗人。**

---

## 一、先承认一个现状：现在这套会"骗人"

今天的 agent 循环里，模型答不出来就静默退回 `_heuristic`，流程照样跑完，
报告照样完整。**如果人不在，没人知道那一步是模型没做成。**

这不是自主，是伪装。三个具体表现：

| 问题 | 现状 | 后果 |
|---|---|---|
| 兜底静默 | 模型失败 → 规则顶上 → 不留痕 | 报告把规则的功劳算成模型的 |
| 动作空间写死 | `ACTIONS` 只有 5 个，而工具总线有 30 个工具 | "让模型控制工具"根本无从谈起 |
| 经验不回流 | `knowledge.py` 只用于排序，不进提示 | 同样的坑，下一台固件再踩一遍 |

**第一优先级不是加能力，是让工具对自己诚实。**

---

## 二、「规则干不了的模型干」—— 难的是边界在哪

这句话本身没问题，问题是**边界不能写死**。

今天的分工是"阶段归规则、目标归模型"，这条线是我拍的。换 7B / 32B 之后，
这条线该往哪移？没人知道。所以正确的做法不是设计一条更好的线，而是：

> **把每个决策点做成可开关的策略，跑对照实验，让数据决定谁来做。**

这就是"自我进化"最现实的第一层 —— 不是模型变聪明，是**边界会自己移动**。

例如同一个决策点，三种策略：

```
always_rule    规则做（快、可复现、但只能按写好的逻辑）
always_model   模型做（慢、可能错、但能处理没见过的情况）
model_then_rule  模型先做，做不出再退回规则（今天的默认）
```

跑同一批固件，比较三种策略的**成功率 / 步数 / 兜底率**，就能回答
"这个决策点值不值得给模型"。换模型之后重跑一遍，边界自己就移了。

---

## 三、"自我进化"能到什么程度（别过度承诺）

分三层，能力递增，但**只有前两层能真正自动**：

### L1 策略自进化（可自动）

决策点参数化（用谁做、温度多少、给多少预算），每次运行记录
「谁做的 / 成没成 / 花了多少」。累积够了就自动选策略。

- 数据来源：今天的**自评表**已经在记 `model_share` / `rejects` / `verdict_accept_rate`；
- 落点：`knowledge.py` 扩成 `policy_stats.json`；
- 判据：同厂商第二台固件，平均步数下降 ≥30%。

### L2 经验自进化（可自动）

失败 → 提炼教训 → 下次进提示。现在 `knowledge.py` 只用于**排序**，这是浪费。

```
"DIR-615 的 /login.cgi 缺 graph_id 会崩，别用带参数的对照组当基线"
"Edimax 的 goform 路由需要 Basic 认证，先试 admin:1234"
```

- 落点：`state_brief` 里加「这台固件/这个厂商，以前踩过什么」；
- 判据：同类固件第二次跑，重复失败次数归零。

### L3 能力自进化（**不能全自动**）

"模型控制各种工具"意味着动作空间要从**工具总线生成**，而不是我手写 5 个。

但要说清楚：**动作空间可以自动扩展，工具本身不能自己长出来。**
模型可以组合已有工具做新事情，但"需要一个新工具"这件事，仍然要人来写。

- 落点：`ACTIONS` 由 `toolbus` 的 30 个工具动态生成 + 每个工具自带 success 判据；
- 判据：模型能在同一台固件上组合出 ≥2 种没被硬编码过的调查路径。

---

## 四、「人不在的时候」最需要的三样东西

这三样**不依赖更强的模型**，现在就该做：

### 4.1 诚实降级（最重要）

兜底不能静默。规则替模型做的每一步，都要在产物里留痕：

```
第 4 步：［规则兜底］probe /apply.cgi —— 模型选了 pages（已做过），退回规则
```

并且报告头部要有一行总结：`模型完成 6/8 步，规则兜底 2 步（原因：多余参数 1、重复动作 1）`。

**判据**：任何一份报告，都能一眼看出哪些结论是模型下的、哪些是规则下的。

### 4.2 卡住就求助，别死循环

现在靠"重复动作检测"防打转，但那是补丁。真正需要的是**进展度量**：

```
连续 N 步没有新候选 / 没有新证据 / 结论数为 0  →  判定卡住
```

卡住之后不是继续烧预算，而是**降级成交接**：

- 停止；
- 写 `handoff.md`：做了什么、发现了什么、卡在哪、下一步建议人看什么；
- 退出码非 0（让 CI / 批处理知道这条没跑完）。

**判据**：预算耗尽时一定有一份 handoff，而不是一个"看起来跑完了"的报告。

### 4.3 交接包（handoff.md）

人来接手时最想知道的三件事：

```markdown
# 交接：<固件> <时间>
## 已经确认的
- /login.cgi 缺 graph_id → 0 字节，服务退出（3/3，已跨 2 个版本）
## 还没确认的
- 真机未验证；公开渠道只查了离线 NVD
## 卡在哪 / 建议下一步
- 反汇编 sbin/httpd 找 graph_id 的处理函数（m2 已生成，路径 /tmp/d615-m2）
- 在线 NVD / Exploit-DB / CNVD 查重
```

## 五、自我进化的护栏（答辩一定会被问）

1. **不让人之外的东西改规则**：模型可以建议"这里该换个策略"，但改 `_heuristic`、
   改验收条件，必须人审。自动改规则 = 无法复现的实验。
2. **经验库要有上限**：教训只进不退会越积越脏，需要定期按"命中率"淘汰。
3. **所有决策可回放**：`trace` 里必须带 `source`，否则"自我进化"无法归因。

---

## 六、落地顺序

| 优先级 | 做什么 | 依赖更强模型？ | 判据 |
|---|---|---|---|
| **P0** | 兜底留痕 + 卡住检测 + `handoff.md` | 否 | 预算耗尽必有交接包 |
| **P1** | 观察层：把响应差异/状态码喂给模型 | 否 | 匿名组 0/5 → ≥3/5 |
| **P2** | 决策点参数化 + 三策略对照 | 否 | 边界由实验数据决定 |
| **P3** | 经验回灌进提示 | 否 | 同类固件重复失败归零 |
| **P4** | 动作空间从 toolbus 生成 | 部分 | 组合出 ≥2 条未硬编码路径 |

**顺序理由**：P0 和 P1 都不依赖模型变强，但现在就在拖后腿 —— P0 决定工具可信不可信，
P1 决定模型有没有材料可推理。P4 最后做，因为它最容易被误当成"智能"。

---

## 七、一句话

> 现在这套的瓶颈不是模型不够强，是**它看不到东西、它的失败没人记、它能动的工具只有 5 个**。
> 换更强的模型，只会让"它看不到东西"这件事更贵。
