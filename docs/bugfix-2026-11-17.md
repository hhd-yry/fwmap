## A 类：直接修

### A1. `poc.channel_of()` —— Cookie / 环境变量类链路会被打错通道

**文件**：`fwmap/poc.py`

**为什么是 bug（静态证明）**

`judge.kind_of()` 里 `if api == "getenv": param = chain.get("source_param")` 说明：
`source_api` 存的是**函数名**，键名在 `source_param`。

而 `channel_of()` 全程用 `api` 判断头部：

| 分支 | 对 `source_api="getenv"` / `source_param="HTTP_COOKIE"` |
|---|---|
| `if "cookie" in api` | `"cookie" in "getenv"` → False |
| 守卫正则 `getenv\s*\(\s*([A-Z_]+)` | guard 是 `getenv("HTTP_COOKIE")`，`(` 后是引号 → 不匹配 |
| `if "http_" in api` | False |
| 兜底 | `return "form", "HTTP_COOKIE"` |

结果：载荷进 POST body，程序读的是 Cookie 头 → **静默打不中**。`tests/test_poc.py` 里
所有用例都是 `websGetVar`（form 通道），没有一条 cookie 用例，所以测试发现不了。

**改法**

```python
def channel_of(chain: dict) -> tuple[str, str]:
    api = (chain.get("source_api") or "").lower()
    param = (chain.get("source_param") or "").strip()
    # source_api 是**函数名**（judge.kind_of 里 `if api == "getenv"` 就是这么用的），
    # 键名在 source_param 里。只看 api 的话，getenv("HTTP_COOKIE") 会被错归成 form，
    # 载荷打进 body 而程序读的是头 —— 静默打不中。
    key = param.lower()

    # 1) 先从字段名认
    if "cookie" in key:
        return "header", "Cookie"
    if key in _HEADER_OF:
        return "header", _HEADER_OF[key]
    if key.startswith("http_"):
        return "header", key[5:].replace("_", "-").title()

    # 2) 字段名认不出，退回 api / 守卫代码。
    #    守卫里的写法带引号，正则必须允许它，否则永远匹配不上。
    if "cookie" in api:
        return "header", "Cookie"
    m = re.search(r"""getenv\s*\(\s*["']?([A-Za-z_]+)""", chain.get("guard") or "")
    gkey = (m.group(1).lower() if m else "")
    if gkey in _HEADER_OF:
        return "header", _HEADER_OF[gkey]
    if gkey.startswith("http_"):
        return "header", gkey[5:].replace("_", "-").title()

    # 3) 整条 query string 都是输入，参数名没有意义
    if key in ("request_uri", "query_string") or "request_uri" in api \
            or "query_string" in api:
        return "query", "x"

    return "form", param
```

**验证**

```python
from fwmap import poc
c = {"source_api": "getenv", "source_param": "HTTP_COOKIE",
     "function": "f", "sink": "strcpy", "sink_category": "bof"}
r = poc.build_requests(c, None)
assert r[0]["channel"] == "header"
assert r[0]["headers"]["Cookie"].startswith("A")
```

### A2. `pages.lookup()` —— 一个 `action="#"` 会让任意函数匹配到假路由

**文件**：`fwmap/pages.py`

**为什么是 bug**

`_norm("#")` 的处理链：去引号 → `"#"` → `split("#")[0]` → `""` → 不以 `/` 开头 → 补成 `"/"`。
于是 `last_seg("/")` = `""`，而 `low.startswith("")` **恒为 True**：

```python
for f in forms:
    seg = last_seg(f["uri"])
    if seg.startswith(low) or low.startswith(seg):   # ← seg == "" 时全命中
```

`<form action="#">` 是极常见的"禁用默认提交"写法。后果：PoC 打到一个不存在的
URL，动态验证必然 `no-crash`，而你会以为是"没打出漏洞"。

同类小号问题：`action="/a"` 这种单字符段，会让所有以 `a` 开头的函数命中。

**改法（三处）**

(a) `_norm` 拒绝非路由，并改用前缀剥离（原来 `lstrip("./")` 是**字符集**剥离，`"../x"` 会被吃成 `"/x"`）

```python
def _norm(uri: str) -> str:
    uri = uri.strip().strip('"\'')
    uri = uri.split("?", 1)[0].split("#", 1)[0]
    while uri.startswith(("./", "../")):
        uri = uri[2:] if uri.startswith("./") else uri[3:]
    if not uri or uri in ("#", "/"):
        return ""                      # 空 action / "#" / 裸斜杠不是路由
    if not uri.startswith("/"):
        uri = "/" + uri
    return uri
```

(b) `forms_of` 里的 `add()` 要在归一化之后也判空

```python
    def add(uri: str, params: list[str]) -> None:
        if not uri:
            return
        u = _norm(uri)
        if not u:                      # ← 新增
            return
        key = (u, tuple(params))
        ...
```

(c) `lookup()` 第二档加长度下限

```python
    def usable(seg: str, min_len: int = 3) -> bool:
        return len(seg) >= min_len

    for f in forms:
        if last_seg(f["uri"]) == low:
            return best([x for x in forms if last_seg(x["uri"]) == low])
    for f in forms:
        seg = last_seg(f["uri"])
        if usable(seg) and (seg.startswith(low) or low.startswith(seg)):
            return best([x for x in forms
                         if usable(last_seg(x["uri"]))
                         and (last_seg(x["uri"]).startswith(low)
                              or low.startswith(last_seg(x["uri"])))])
```

**验证**

```python
from fwmap import pages
forms = pages.forms_of('<form action="#"><input name="a"></form>'
                       '<form action="/goform/formWds"><input name="b"></form>')
assert pages.lookup(forms, "formDLNAserver") is None      # 修前会返回 "/"
assert pages.lookup(forms, "formWds")["uri"] == "/goform/formWds"
```

### A3. `merge_mango._routes()` —— 把文件系统路径当成路由输出

**文件**：`fwmap/merge_mango.py`

**为什么是 bug**

`_RE_ROUTE` 只按后缀过滤（`.c/.h/.so/.bin/.txt/.html/.htm`），没排除 `/etc/`、`/tmp/`、
`/dev/` 这些根。而 CVE 描述里经常写 `cp /etc/passwd /tmp/pwned`。

后果：合并报告会写「CVE 描述里给出的路由是：**/etc/passwd, /tmp/pwned**」。
这句恰好是整个报告里最有说服力的一句，写错比不写更糟。

**改法**

在 `_routes()` 里，模块级加一个常量：

```python
# 描述里常出现文件路径（cp /etc/passwd /tmp/x），它们不是路由。
# 只按后缀过滤会漏掉这些，报告里就会出现「路由是 /etc/passwd」。
_FS_PREFIX = ("/etc/", "/tmp/", "/dev/", "/proc/", "/sys/", "/bin/", "/sbin/",
              "/usr/", "/var/", "/lib/", "/opt/", "/root/")
```

循环里加一行：

```python
    for m in _RE_ROUTE.findall(desc or ""):
        m = m.rstrip(".,;:")
        if m.lower().startswith(_FS_PREFIX):
            continue
        if m.lower().endswith((".c", ".h", ".so", ".bin", ".txt", ".html", ".htm")):
            continue
        if m not in out:
            out.append(m)
```

**验证**

```python
from fwmap import merge_mango
assert merge_mango._routes("cp /etc/passwd /tmp/pwned; route /goform/telnet") == ["/goform/telnet"]
```

### A4. `plugins.py` —— 两个独立问题

**文件**：`fwmap/plugins.py`

#### (a) 占位符写错会掀翻整个工具调用

```python
try:
    argv.append(part.format(**kwargs))
except KeyError as e:
    return {"ok": False, "summary": f"参数没提供：{e}"}
```

`{}` → `IndexError`；`{a.b}` → `AttributeError`。都不在捕获范围，会一路抛到
`tools_api.call`。而这段代码的设计目标正是"失败结构化、不炸主流程"。

**改法**

```python
            try:
                argv.append(part.format(**kwargs))
            except KeyError as e:
                return {"ok": False, "summary": f"参数没提供：{e}"}
            except (IndexError, AttributeError, ValueError) as e:
                return {"ok": False,
                        "summary": f"manifest 里的占位符写错了（{part!r}）："
                                   f"{type(e).__name__}"}
```

#### (b) UTF-8 环境漏了 `py`

```python
exe = os.path.basename(argv[0]).lower() if argv else ""
if exe.startswith("python") and not (...):
    env.update(_UTF8_ENV)
```

仓库根目录的 `fwmap.cmd` 用的是 **`py -3`**（`py.exe`）。manifest 里手写 `"cmd": ["py", ...]`
就拿不到 UTF-8，中文输出变 `\ufffd` —— 正是注释里说"真实对接时踩出来的坑"那一个。

**改法**

```python
    exe = os.path.basename(argv[0]).lower() if argv else ""
    if exe.endswith(".exe"):
        exe = exe[:-4]
    is_py = exe.startswith("python") or exe == "py"
    if is_py and not ({"PYTHONUTF8", "PYTHONIOENCODING"} & set(explicit)):
        env.update(_UTF8_ENV)
```

### A5. `dyn.py` —— 重复调用 + 静默丢弃未知词汇

**文件**：`fwmap/dyn.py`

#### (a) `_kill_guest` 在 `finally` 里写了两遍

```python
    finally:
        _kill(proc)
        _kill_guest(runtime["exe"])
        _kill_guest(runtime["exe"])      # ← 删掉这行
```

#### (b) 非 `keep` 词汇会被静默丢弃

`run_dyn()` 和 `run()` 各有一处：

```python
chains = [c for c in ... if c.get("verdict", "keep") == "keep"]
```

如果哪天 flow 里混进 `CONFIRMED` / `SUPPORTED`（比如把 agent 结果回写），
**全部链被丢弃**，只报"flow 里没有可用的链"——看不出是词汇不认识。

`run_dyn()` 里改成：

```python
    raw_chains = [c for c in (chains_or_flow if isinstance(chains_or_flow, list)
                              else (chains_or_flow.get("chains") or []))]
    chains = [c for c in raw_chains if (c.get("verdict") or "keep") == "keep"]
    other = {c.get("verdict") for c in raw_chains} - {"keep", "demoted", None}
    if other:
        log(f"[!] flow 里有非 keep/demoted 的 verdict：{sorted(map(str, other))}，"
            f"这些链被跳过了（词汇不认识时不要静默）")
```

`run()` 里同样加一行提示即可。

## B 类：确实是 bug，但会改变判定结果

### B1. `judge.judge()` —— 归纳源可以拿到 `high` confidence

```python
conf = "high" if agree >= 0.99 else ("medium" if agree >= 0.67 else "low")
```

完全不看 `chain["weak"]` / `chain["induced_source"]`。而 `http_param(induced)` 在
`REMOTE_KINDS` 里，所以"归纳源 + 3/3 一致"能产出 `high confidence` 的 `CONFIRMED` ——
与 README 里"归纳=弱证据"、`extract.py` 里"单独成组、不进强源组"的口径直接矛盾。

**改法**

```python
    conf = "high" if agree >= 0.99 else ("medium" if agree >= 0.67 else "low")
    # 归纳出来的源/汇是弱证据，一致度再高也不能给 high —— 口径要和 extract/m3flow 一致
    if chain.get("weak") or chain.get("induced_source") or chain.get("induced_sink"):
        conf = "medium" if conf == "high" else conf
```

**影响**：一部分 `CONFIRMED` 的 confidence 从 high 降为 medium。verdict 不变。

### B2. `judge._reassign_breaks_taint()` —— 只认 `source_param`，漏了 `via`

```python
    if "=" in text:
        rhs = text.split("=", 1)[1]
        src = (chain.get("source_param") or "").strip()
        if src and len(src) >= 2 and re.search(rf"\b{re.escape(src)}\b", rhs):
            return False
```

这里要同时容纳两种形态，只认一个都会错：

| 形态 | 例子 | 代码右侧实际出现的是 |
|---|---|---|
| 源是取值函数 | `websGetVar(a1,"rootAPmac")` → 污染变量 `uVar3` | **`via`**；`"rootAPmac"` 是字符串字面量，不会出现在赋值右侧 |
| 源就是函数参数 | Edimax `formUploadIE` 的 `param_3` | **`source_param`**；`via` 反而是个不出现的指针名 |

于是：

- 只认 `source_param` → `uVar3 = uVar3 + 1` 这种自引用累加被误判成"污染已断"，真链被 `REFUTED`
- 只认 `via` → Edimax `*(int *)mid = *(int *)mid + param_3` 反过来被判错

**这条是既有测试救回来的。** 第一版改成"只用 `via`"，跑 `tests/test_judge_rules.py`
的「累加式赋值不算断链」直接挂 —— 那条用例的材料正是 Edimax 真实报告里的
`formUploadIE`。没有它，会把一条真实链重新判错，而且没人会发现。

**实际改法（两个名字都认）**

```python
    if "=" in text:
        rhs = text.split("=", 1)[1]
        for nm in ((chain.get("via") or ""), (chain.get("source_param") or "")):
            nm = nm.strip()
            if nm and nm != "inline" and re.search(rf"\b{re.escape(nm)}\b", rhs):
                return False
```

**影响**：一部分本该 `REFUTED` 的链会保留下来（召回升、精确率可能降）。
建议用评测集确认。单独回滚：`git checkout 94219b2 -- fwmap/agent/judge.py`
