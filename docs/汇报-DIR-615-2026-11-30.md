# 汇报材料：DIR-615 `login.cgi` 未认证崩溃

> **汇报日期**：2026-11-30（周一）
> **材料整理日期**：2026-11-28
> **证据等级**：**candidate（候选）** —— 不是"复现"，也不是"新 0day"
> **一句话**：一个不带参数的 GET 请求，就能让这台路由器的 Web 管理服务退出。

---

## 一、电梯陈述（30 秒，背下来）

> 在 D-Link DIR-615 的旧固件上，Web 服务处理 `/login.cgi` 时没有校验必需参数
> `graph_id`。不带这个参数访问，服务进程直接退出（SIGSEGV），管理界面随即不可用。
> 不需要登录、不需要 payload、一个请求就够。
> 我们在 2010 和 2011 两个版本上复现，2015 年重构后的版本已经没有这个接口。
> 目前公开漏洞库里查不到对应记录，但**还没做真机验证，也没联系厂商**，
> 所以我们把它标成"候选漏洞"，不叫 0day。

---

## 二、三分钟口述稿

### 1. 怎么发现的（30 秒）

工具解包固件拿到 rootfs，抽出 104 条 Web 路由，然后在模拟器里起设备自带的
`sbin/httpd`，把候选端点逐条发过去做三对照判定。

### 2. 发现了什么（40 秒）

| 请求 | 响应 | 服务状态 |
|---|---|---|
| `GET /index.asp` | 6299 字节 200 | 存活 |
| `GET /apply.cgi` | 6299 字节 200 | 存活 |
| `GET /login.cgi?graph_id=1` | 6299 字节 200（正常登录页） | 存活 |
| **`GET /login.cgi`** | **0 字节** | **进程退出（`status=crash`）** |
| `GET /<随机 12 字母>` | 248 字节 404 | 存活 |

关键在于**同一轮里**：前一个请求还返回 6299 字节，下一个就 0 字节、进程没了。
所以不是服务没起来，是这个请求把它打死的。

> 字节数口径：以上是**读到 EOF 的完整响应**（2026-11-28 实测）。
> 早期记录里的 1818 是单次 `recv` 的首包长度，不是完整正文；
> 判定只看"和 404 比像不像"，不受影响，但汇报时数字要统一。

### 3. 为什么可信（40 秒）

- **三对照**：负对照（随机路径）、正对照（`GET /`）、候选，缺一不可；
- **可重复**：一键脚本连发 3 次，3/3 崩；模型实验里 5 轮独立运行，5/5 判出；
- **跨版本**：C2 3.03（2010-10）和 E4 3.08（2011-08）都崩，不是单个构建的偶然；
- **版本边界清晰**：2015 年的 A(A1A) 2.5.12 里 `/login.cgi` 直接 404 ——
  那代重构成 busybox + 模板栈，接口已经不存在了。

### 4. 意味着什么（30 秒）

无认证、单请求、可重复 → 局域网内任何人可以让管理界面下线。
CVSS 3.1 估算 7.5（`AV:N/AC:L/PR:N/UI:N/S:U/C:N/I:N/A:H`）。

**但这是可用性问题，不是 RCE。** 报告里我写的是 DoS，没有夸大成命令执行。

### 5. 还差什么（40 秒）

三件事：真机验证（排除 qemu 因素）、在线渠道全查（现在只查了离线 NVD 快照）、
厂商或 CNA 确认。三条都过才叫"漏洞"，现在只能叫"候选"。

## 四、它不是什么（这一页最重要）

汇报最容易翻车的地方是**说过头**。以下四句千万别说：

| ❌ 别说 | ✅ 该说 |
|---|---|
| "我们发现了一个 0day" | "我们发现一个候选漏洞，还没经过厂商确认" |
| "可以远程执行代码" | "是拒绝服务，不是 RCE" |
| "影响所有 DIR-615" | "只影响 2010–2011 的旧 `.asp` 架构；2015 版接口已移除" |
| "已经在设备上验证过" | "在 qemu 模拟环境里复现，真机还没做" |

**如果被问"那不就是重启一下吗"**，可以这样答：

> 对，影响面是可用性，不是控制权。但三个因素让它值得记录：
> 一是**无需认证**，局域网内任何人都能触发；
> 二是**可重复**，没有速率限制，看门狗拉起后可以接着打；
> 三是**版本边界清楚**，2010–2011 这批老设备早就 EOL，
> 厂商大概率不修，实际暴露期会很长。
> 我们按 DoS 如实定级 7.5，没有往 RCE 上靠。

## 五、备问清单（九个最可能被问的）

**Q1：这算新漏洞吗？**
不能这么讲。我们查了离线 NVD（42 万条，2026-11 快照）：
按 `DIR-615` 搜到 **6 条**，逐条比对**没有**"缺参数导致崩溃"这一条；
按 `DIR-615` + `graph_id` 直接搜是 **0 命中**。
但"没查到"不等于"没人知道"，而且没做真机、没联系厂商。所以按学术规范标 **candidate**。

**Q2：同型号是不是已经有 CVE 了？**
有，而且很近 —— **CVE-2021-37388**：DIR-615 **C2 3.03WW** 的 `ping_response.cgi`
里 `ping_ipaddr` 参数存在缓冲区溢出，POST 超长值能打崩 Web 服务，甚至可能 RCE。

**但不是同一条**，三点不同：

| | CVE-2021-37388 | 我们这条 |
|---|---|---|
| 端点 | `ping_response.cgi` | `login.cgi` |
| 触发 | POST 带超长 `ping_ipaddr` | GET **不带** `graph_id` |
| 类型 | 缓冲区溢出 | 缺参数导致的异常路径 |

**一定要主动说这一条**，否则被老师问出来会很被动。
主动说的版本是："同型号有一条相邻 CVE，我们查过，端点和触发方式都不同。"

**Q3：会不会是你模拟环境的问题？**
三个理由排除：① 同一轮里正对照返回 1818 字节，说明服务是活的；
② 带 `graph_id` 的同一端点正常返回，说明不是路由本身坏；
③ 两个不同固件版本、不同 httpd 二进制（473,712 vs 435,592 字节）都崩。
最后一道保险是真机，我们没做，所以不把话说满。

**Q4：根因是什么？**
**还没做反汇编，不能编。** 我们的假设是 `websGetVar(wp, "graph_id", NULL)`
返回 NULL 后未判空，但这只是假设。下一步用 Ghidra 定位 handler 确认，
那样报告能从"某请求导致崩溃"升级成"第 X 条指令对空指针解引用"。

**Q5：能拿 CVE 吗？**
路径有三条：D-Link 安全响应、CNVD、MITRE CNA。但前置条件是真机验证
（或 FirmAE 全系统模拟）+ 影响范围。这台设备 2010 年上市、早已 EOL，
厂商大概率只确认不修 —— 这不影响漏洞成立，但要有心理准备。

**Q6：这个漏洞和你的"大模型"有什么关系？**
**直接说是：关系不大，要说清楚分层。** 这条崩溃是在**动态验证阶段**由固定规则
发现的（三对照判定 + 0 字节），不是模型判断出来的。
模型的作用是另一件事：在 36 条候选里挑先探哪一条。
具名条件下第 2 次就挑中 `/login.cgi`，隐藏名字后 5 轮一次没挑中。
这恰好说明模型的能力边界 —— 说清这一点比把功劳都归给模型更可信。

**Q7：为什么 2015 版没有？**
那年 Web 栈整体重写成 busybox httpd + `webs/www` 模板，`login.cgi` 这个 CGI
根本不存在了（实测 404）。所以缺陷绑定在旧架构上，不是"所有 DIR-615 都中"。

**Q8：危害到底多大？能给个场景吗？**
局域网内（或开了远程管理的 WAN 侧），攻击者发一个 GET 就能让管理页面下线；
设备转发功能不受影响，但用户改不了配置、看不了状态。
结合 EOL 现状，实际暴露窗口很长。**不要说能拿 shell。**

**Q9：下一步做什么？**
三件：① 反汇编找根因（半天到一天）；② 在线 NVD / Exploit-DB / CNVD 全查（半天）；
③ 真机或 FirmAE 验证（看设备）。做完这三件再决定要不要提交 CVE。

## 六、现场演示（可选，2 分钟）

一条命令，输出会自己说话：

```bash
sudo bash tools/poc-dir615-login-cgi.sh /home/ubuntu/lab/d615/root
```

预期输出：

```
== 对照组 A：正常页面应该活着 ==
  GET /index.asp            → 305 字节 200 OK   进程=up
== 对照组 B：带 graph_id 应该活着 ==
  GET /login.cgi?graph_id=1 → 1818 字节 200 OK  进程=up
== 触发：不带 graph_id ==
  第 1 次：GET /login.cgi → 0 字节  进程=down
  第 2 次：GET /login.cgi → 0 字节  进程=down
  第 3 次：GET /login.cgi → 0 字节  进程=down
```

**演示前先跑一遍确认环境好的**（VM 要开着、qemu 在）。
演示时先讲对照组，再讲触发 —— 顺序反了容易被当成"服务没起来"。
