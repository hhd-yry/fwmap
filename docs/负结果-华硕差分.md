# 负结果：华硕 RT-AC68U 两次固件差分

> 目标：不找「最新固件里的 0day」，而是**拿相邻两个版本比，从补丁反推哪里出过事**，
> 再看同一处还有没有没修干净的兄弟点。
> 结论：**找到两条被修掉的安全问题，但没找到新的可利用漏洞。**

## 1. 样本

| | 版本 | 日期 | rc 大小 | httpd 大小 |
|---|---|---|---|---|
| 旧 | 3.0.0.4.386_52062 | 2025-10-27 | 1,477,968 | 476,576 |
| 新 | 3.0.0.4.386_52102 | 2026-05-12 | 1,481,528 | 476,580 |

`httpd` 只差 **4 字节**，`rc` 差 **3.5 KB** —— 补丁基本都在 `rc`（系统管家）里。

## 2. 差分结果

### ① 新版加了 MAC 格式校验（旧版没有）

```
新增字符串：
  amas_legal_mac_format
  [AMASLIB][%s:(%d)] %s not allow illegal mac format!
```

旧版里完全没有这两个串。也就是说 **2025-10 的版本接受非法 MAC 格式**，
2026-05 才补上校验。

这说明 AMAS（AiMesh）链路里曾有一条「网络传来的 MAC 字符串未校验」的问题面。
但**是不是被完整修掉**没验证完：rc 是 PIE，字符串走重定位表，静态找不到引用，
需要 Ghidra 脚本才能定位到被改的函数。

### ② 新版去掉了 wget 的 `--no-check-certificate`

```
旧：wget ... --no-check-certificate 'https://router.uu.163.com/...' -O /tmp/uu/script_url
新：wget ... 'https://router.uu.163.com/...' -O /tmp/uu/script_url
```

旧版会**不校验证书**就从远端下载脚本，然后执行 `/tmp/uu/uuplugin_monitor.sh`。
中间人改掉那个脚本 = 以 root 执行任意代码。

这属于「已被厂商修掉的真实问题」，不是新漏洞 —— 但它是一条**可复现的攻击链**，
如果要做演示，比「抽象的候选链」具体得多。

## 3. 为什么没继续

- `rc` 是 PIE，字符串地址在 `.rel.dyn` 里，直接搜字面量搜不到；
- 我们手上没有二进制差分工具（Diaphora/BinDiff 一类），只能用字符串集合比；
- 要定位「被改的那个函数」，得写一个 Ghidra 脚本遍历引用，属于下一轮的工作量。

## 4. 这轮方法上的收获

**字符串差分是性价比很高的第一步**：两个固件、两条 `strings | sort`、一次 `comm`，
就能看出厂商这一版在补什么。对「找新漏洞」帮助有限，但对「判断这个固件最近出过什么事」
几乎是零成本。

下一步如果还要挖，正确顺序应该是：
1. 用 Ghidra 脚本把「引用了新增字符串的函数」定位出来；
2. 看该函数在旧版里长什么样（对比反编译）；
3. 在这一处周边找**同类但没加校验**的兄弟函数。
