## 二、修掉的两个真 bug（比任何一条漏洞都重要）

### bug 1：探测请求用了 POST

```
routes._req() 默认构造 POST + body x=1
→ DIR-615 的 httpd 对静态 .asp 的 POST 直接关连接（0 字节）
→ /index.asp 判成 unknown，所有路由验收全线失败
```

改成默认 **GET** 后：`/index.asp` → 1818B → handler。

### bug 2：每个请求都重启一次服务

`routes.probe` 逐地址 `run_request`，chroot 进程没退干净 → 下一轮 bind 失败 → 空响应。
新增 `dyn.ServiceSession`（一次启动、多次请求、按需重启）后，连打 9 次全部 200，
耗时从「N × 3–8 秒」降到「1 次启动 + N 次请求」。

## 五、新候选：DIR-615 `/login.cgi` 未认证崩溃

```
GET /login.cgi              → 0B，SIGSEGV，服务死
GET /login.cgi?graph_id=1   → 1818B，200 Ok
POST /login.cgi             → 0B，SIGSEGV
```

3 次里 2 次稳定崩溃，带 `graph_id` 则不崩（输入相关，排除环境假象）。
查重：`DIR-615 graph_id` 0 条，`login.cgi` 只命中 CVE-2017-9542（认证绕过，不同问题）。

## 六、事故与修复：fork 炸弹

Edimax 的 `usr/sbin/httpd` 是 **busybox 符号链接**，被当服务跑时把自己当 CGI 再执行，
滚出 **508 个进程、load 513**，SSH 一度不可用。

修复：所有服务子进程加资源围栏

```python
RLIMIT_NPROC = 64
RLIMIT_CPU   = 120
```

实测同一场景连打 6 次，进程数恒为 1。
